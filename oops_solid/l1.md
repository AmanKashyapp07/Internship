## 1. What is OOP?

**Object-Oriented Programming (OOP)** is a programming paradigm that organises software around **objects** — bundles of state (data) and behaviour (functions) — rather than around logic and procedures.

> **Interview One-liner**: OOP encapsulates data and behaviour together, enabling modular, reusable, and maintainable code.

---

## 2. Class vs Object

| Concept   | Definition                                       | Analogy               |
|-----------|--------------------------------------------------|-----------------------|
| **Class** | Blueprint / template that defines attributes and methods | Cookie-cutter mould   |
| **Object**| Runtime instance of a class that occupies memory | Actual cookie         |

### C++ Example

```cpp
#include <iostream>
#include <string>
using namespace std;

class Car {                     // class = blueprint
public:
    string brand;               // attribute (member variable)
    int    speed;

    void accelerate() {         // method (member function)
        speed += 10;
        cout << brand << " going at " << speed << " km/h\n";
    }
};

int main() {
    Car c1;                     // object = instance
    c1.brand = "Tesla";
    c1.speed  = 0;
    c1.accelerate();            // Tesla going at 10 km/h
}
```

## 3. Memory Model — Stack vs Heap

Understanding where objects live is crucial for interviews at system-level companies.

| Feature           | Stack                            | Heap                              |
|-------------------|----------------------------------|-----------------------------------|
| Allocation        | Automatic (LIFO)                 | Manual (`new`) or RAII            |
| Deallocation      | Auto when scope ends             | Manual (`delete`) or smart pointer|
| Speed             | Faster (no fragmentation)        | Slower (OS allocates)             |
| Size Limit        | Small (~1–8 MB default)          | Limited only by available RAM     |
| Object Lifetime   | Scoped                           | Until explicitly freed            |

```cpp
// Stack allocation
Car stackCar;                   // destroyed at end of scope

// Heap allocation
Car* heapCar = new Car();       // lives until deleted
heapCar->brand = "BMW";
delete heapCar;                 // MUST free to avoid memory leak

// Modern C++ — prefer smart pointers
#include <memory>
auto smartCar = make_unique<Car>();   // auto-deleted
```

> **Interview Trap**: Forgetting `delete` on heap objects → **memory leak**. Use `valgrind` or smart pointers.

## 4. Access Modifiers

| Modifier      | Same Class | Derived Class | Outside World |
|---------------|:----------:|:-------------:|:-------------:|
| `public`      | ✅          | ✅             | ✅             |
| `protected`   | ✅          | ✅             | ❌             |
| `private`     | ✅          | ❌             | ❌             |

```cpp
class BankAccount {
private:
    double balance;         // hidden from outside

protected:
    string ownerName;       // accessible by derived classes

public:
    void deposit(double amt) {
        if (amt > 0) balance += amt;
    }
    double getBalance() const { return balance; }
};
```

### Default Access in C++ (tricky!)

```cpp
class Foo { int x; };   // private by default
struct Bar { int x; };  // public by default
```

> **Interview Q**: What is the difference between `class` and `struct` in C++?
> **Answer**: Only default access modifier (`private` vs `public`) and default inheritance type. Functionally identical otherwise.

## 5. The Four Pillars of OOP

```
┌─────────────────────────────────────────────────┐
│              Four Pillars of OOP                │
├────────────────┬───────────────────────────────┤
│ Encapsulation  │ Bundling data + behaviour;     │
│                │ hiding internal state          │
├────────────────┼───────────────────────────────┤
│ Abstraction    │ Exposing only WHAT, not HOW    │
├────────────────┼───────────────────────────────┤
│ Inheritance    │ Deriving new classes from      │
│                │ existing ones (IS-A)           │
├────────────────┼───────────────────────────────┤
│ Polymorphism   │ One interface, many forms      │
│                │ (compile-time & runtime)       │
└────────────────┴───────────────────────────────┘
```

Each pillar is covered in detail in subsequent lectures. This section provides a quick preview.

### 5.1 Encapsulation (Preview)
```cpp
class Temperature {
private:
    double celsius;
public:
    void setTemp(double c) {
        if (c < -273.15) throw invalid_argument("Below absolute zero");
        celsius = c;
    }
    double getTemp() const { return celsius; }
};
```

### 5.2 Abstraction (Preview)
```cpp
class Shape {               // abstract concept
public:
    virtual double area() = 0;  // pure virtual — forces derived classes to implement
};
class Circle : public Shape {
    double r;
public:
    Circle(double r) : r(r) {}
    double area() override { return 3.14159 * r * r; }
};
```

### 5.3 Inheritance (Preview)
```cpp
class Animal {
public:
    void breathe() { cout << "Breathing...\n"; }
};
class Dog : public Animal {     // Dog IS-A Animal
public:
    void bark() { cout << "Woof!\n"; }
};
```

### 5.4 Polymorphism (Preview)
```cpp
Shape* s = new Circle(5);
cout << s->area();          // runtime dispatch via vtable
```

## 6. `this` Pointer

Every non-static member function receives an implicit `this` pointer pointing to the calling object.

```cpp
class Counter {
    int count = 0;
public:
    Counter& increment() {
        this->count++;
        return *this;           // enables method chaining
    }
    void print() const { cout << count << "\n"; }
};

int main() {
    Counter c;
    c.increment().increment().increment().print();  // 3
}
```

> **Interview Q**: What is `this`? Can a static member function access `this`?
> **Answer**: `this` is an implicit pointer to the invoking object. Static functions are not tied to any instance, so they **cannot** access `this`.

## 7. Static Members

```cpp
class MathUtils {
public:
    static const double PI;             // shared across all instances
    static int instanceCount;

    MathUtils() { instanceCount++; }
    ~MathUtils() { instanceCount--; }

    static double circleArea(double r) {
        return PI * r * r;              // no `this` needed
    }
};

double MathUtils::PI = 3.14159265358979;
int    MathUtils::instanceCount = 0;
```

| Feature          | Static Member Variable     | Static Member Function |
|------------------|----------------------------|------------------------|
| Shared across    | All instances              | All instances          |
| `this` access    | ❌                          | ❌                      |
| Accessed via     | `Class::var` or `obj.var`  | `Class::func()`        |

## 8. Scope Resolution Operator `::`

```cpp
int x = 10;                     // global x

class Foo {
public:
    int x = 20;                 // member x
    void show() {
        int x = 30;             // local x
        cout << x;              // 30 (local)
        cout << this->x;        // 20 (member)
        cout << ::x;            // 10 (global) via ::
    }
};
```

## 9. Common Interview Questions (L1)

| # | Question | Key Answer |
|---|----------|------------|
| 1 | What is OOP? Name its 4 pillars. | Encapsulation, Abstraction, Inheritance, Polymorphism |
| 2 | Class vs object? | Class = blueprint, Object = runtime instance |
| 3 | Stack vs Heap for objects? | Stack = fast, auto-managed, small; Heap = manual, large, flexible |
| 4 | `class` vs `struct` in C++? | Default access: `private` vs `public` |
| 5 | What is `this` pointer? | Implicit pointer to calling object; unavailable in static methods |
| 6 | Can you have a class without objects? | Yes — e.g., utility class with only static methods |
| 7 | What is a memory leak? | Heap object not deleted → OS cannot reclaim that memory |
| 8 | Why use smart pointers? | RAII — auto-delete when out of scope; prevents leaks |

## 10. Quick-Revision Snapshot

```
Class   → Blueprint (no memory until instantiated)
Object  → Instance (allocated on Stack or Heap)

Access Modifiers:
  private   → class only
  protected → class + derived
  public    → everywhere

this      → pointer to current object (not in static functions)
static    → shared across all instances; no `this`

Stack: fast, small, auto-managed
Heap:  slow, large, must delete (or use unique_ptr / shared_ptr)
```
