## 1. Constructors

A **constructor** is a special member function called automatically when an object is created. It has the same name as the class and no return type.

---

### 1.1 Types of Constructors

#### Default Constructor
```cpp
class Point {
public:
    int x, y;
    Point() : x(0), y(0) {}    // default constructor
};

Point p;                        // calls Point()
```

#### Parameterised Constructor
```cpp
class Point {
public:
    int x, y;
    Point(int x, int y) : x(x), y(y) {}
};

Point p(3, 4);
```

#### Copy Constructor
```cpp
class Point {
public:
    int x, y;
    Point(int x, int y) : x(x), y(y) {}

    // Copy constructor — takes const reference to same type
    Point(const Point& other) : x(other.x), y(other.y) {
        cout << "Copy constructor called\n";
    }
};

Point a(1, 2);
Point b = a;        // copy constructor called
Point c(a);         // also copy constructor
```

#### Move Constructor (C++11)
```cpp
class Buffer {
    int* data;
    size_t size;
public:
    Buffer(size_t n) : size(n), data(new int[n]) {}

    // Move constructor — "steals" resources from rvalue
    Buffer(Buffer&& other) noexcept : data(other.data), size(other.size) {
        other.data = nullptr;   // prevent double-free
        other.size = 0;
        cout << "Move constructor called\n";
    }

    ~Buffer() { delete[] data; }
};

Buffer b1(100);
Buffer b2 = std::move(b1);   // move constructor — no deep copy!
```

#### Delegating Constructors (C++11)
```cpp
class Rectangle {
    double w, h;
    string color;
public:
    Rectangle(double w, double h, string c) : w(w), h(h), color(c) {}
    Rectangle(double w, double h) : Rectangle(w, h, "white") {}  // delegates
    Rectangle() : Rectangle(1.0, 1.0) {}                         // delegates
};
```

### 1.2 Initialiser List — Why It Matters

```cpp
class Foo {
    int x;
    const int cx;       // MUST be initialised in initialiser list
    int& rx;            // MUST be initialised in initialiser list
    string name;        // initialised before constructor body

public:
    // GOOD: initialiser list — members initialised directly
    Foo(int a, int& ref, string n) : x(a), cx(a), rx(ref), name(n) {}

    // BAD: assignment in body (name is default-constructed then assigned — wasteful)
    Foo(int a, string n) {
        x    = a;
        name = n;       // string: default-construct + operator= — two operations!
    }
};
```

> **Interview Q**: Why prefer initialiser lists?  
> **Answer**: 1) Required for `const`/reference members. 2) Initialises directly (no default-construct + assign). 3) Order matches member declaration order (not initialiser list order).

> **Trap**: Members are initialised in **declaration order**, not initialiser list order!

```cpp
class Trap {
    int b;
    int a;  // declared after b, so initialised after b
public:
    Trap(int x) : a(x), b(a) {}  // b is initialised BEFORE a — b gets garbage!
};
```

---

### 1.3 Explicit Keyword

```cpp
class Wrapper {
    int value;
public:
    explicit Wrapper(int v) : value(v) {}
};

void process(Wrapper w) { /* ... */ }

int main() {
    Wrapper w(42);      // OK — direct initialisation
    // Wrapper w2 = 42; // ERROR — implicit conversion blocked by explicit
    // process(42);     // ERROR — implicit conversion blocked
    process(Wrapper(42)); // OK — explicit
}
```

> **Best Practice**: Mark single-argument constructors `explicit` to prevent surprise implicit conversions.

## 2. Destructors

A **destructor** is called when an object goes out of scope or is explicitly deleted. It cleans up resources.

```cpp
class FileHandler {
    FILE* file;
public:
    FileHandler(const char* path) {
        file = fopen(path, "r");
        if (!file) throw runtime_error("Cannot open file");
    }
    ~FileHandler() {
        if (file) fclose(file);   // guaranteed cleanup — RAII
        cout << "File closed\n";
    }
};

void readFile() {
    FileHandler fh("data.txt");   // opened
    // ... read data ...
}   // fh destroyed here — file ALWAYS closed, even on exception
```

---

### 2.1 Virtual Destructor — CRITICAL

```cpp
class Base {
public:
    ~Base() {}   // NON-virtual — DANGEROUS!
};

class Derived : public Base {
    int* bigData;
public:
    Derived() : bigData(new int[1000]) {}
    ~Derived() { delete[] bigData; }   // may never run!
};

int main() {
    Base* obj = new Derived();
    delete obj;   // ONLY Base::~Base() is called — MEMORY LEAK!
}
```

```cpp
class Base {
public:
    virtual ~Base() {}   // virtual — correct!
};

// Now delete obj calls Derived::~Derived() then Base::~Base()
```

> **Rule**: If a class has **any virtual function**, give it a **virtual destructor**.  
> Even better: any class meant to be a base class should have `virtual ~Base() = default;`

## 3. Rule of Three / Five / Zero

### Rule of Three (pre-C++11)
If you define **any** of:
1. Destructor
2. Copy constructor
3. Copy assignment operator

…you probably need to define **all three**.

```cpp
class Matrix {
    double* data;
    int rows, cols;

public:
    // Constructor
    Matrix(int r, int c) : rows(r), cols(c), data(new double[r*c]()) {}

    // 1. Destructor
    ~Matrix() { delete[] data; }

    // 2. Copy Constructor (deep copy)
    Matrix(const Matrix& other) : rows(other.rows), cols(other.cols),
                                   data(new double[other.rows * other.cols]) {
        copy(other.data, other.data + rows*cols, data);
    }

    // 3. Copy Assignment Operator
    Matrix& operator=(const Matrix& other) {
        if (this == &other) return *this;   // self-assignment check

        delete[] data;                       // free existing resource
        rows = other.rows; cols = other.cols;
        data = new double[rows * cols];
        copy(other.data, other.data + rows*cols, data);
        return *this;
    }
};
```

### Rule of Five (C++11+)
Add move constructor and move assignment:

```cpp
// 4. Move Constructor
Matrix(Matrix&& other) noexcept
    : rows(other.rows), cols(other.cols), data(other.data) {
    other.data = nullptr;
    other.rows = other.cols = 0;
}

// 5. Move Assignment Operator
Matrix& operator=(Matrix&& other) noexcept {
    if (this == &other) return *this;
    delete[] data;
    data = other.data;
    rows = other.rows; cols = other.cols;
    other.data = nullptr;
    other.rows = other.cols = 0;
    return *this;
}
```

### Rule of Zero (Modern C++)
Use RAII wrappers (smart pointers, `std::vector`, `std::string`). Let the compiler generate everything.

```cpp
class ModernMatrix {
    vector<double> data;    // vector manages memory
    int rows, cols;
public:
    ModernMatrix(int r, int c) : rows(r), cols(c), data(r*c, 0.0) {}
    // No destructor, copy/move ctor/assignment needed — all compiler-generated!
};
```

## 4. Shallow vs Deep Copy

```cpp
class ShallowProblem {
public:
    int* arr;
    int  size;

    ShallowProblem(int n) : size(n), arr(new int[n]) {}
    // Compiler-generated copy: copies the POINTER, not the data!
};

int main() {
    ShallowProblem a(5);
    ShallowProblem b = a;   // shallow copy — b.arr == a.arr (same pointer!)
    delete[] b.arr;         // DOUBLE FREE when a is destroyed — CRASH
}
```

```
Shallow Copy:           Deep Copy:
┌───┐                   ┌───┐         ┌───┐
│ a │── arr ──→ [data]  │ a │── arr ──→ [data]
└───┘     ↑            └───┘         └───┘
          │             ┌───┐              ↓ (new allocation)
┌───┐     │             │ b │── arr ──→ [copy of data]
│ b │─────┘             └───┘
└───┘
Two pointers to same allocation!  Separate allocations!
```

## 5. Static Members & Friend

### 5.1 Static Member Functions & Variables

```cpp
class IDGenerator {
    static int nextId;          // shared across all instances

public:
    static int generate() { return nextId++; }  // no `this`
    static int current()  { return nextId; }
};

int IDGenerator::nextId = 1000;  // define outside class

int main() {
    cout << IDGenerator::generate();  // 1000
    cout << IDGenerator::generate();  // 1001
    // IDGenerator::nextId;  // ERROR — private
}
```

### 5.2 Friend Functions and Classes

```cpp
class Matrix;

class Vector {
    double data[3];
public:
    Vector(double x, double y, double z) : data{x, y, z} {}
    friend double dot(const Vector& a, const Vector& b);  // friend function
    friend class Matrix;                                   // friend class — Matrix can access private
};

// Friend function: not a member, but can access private members
double dot(const Vector& a, const Vector& b) {
    return a.data[0]*b.data[0] + a.data[1]*b.data[1] + a.data[2]*b.data[2];
}

int main() {
    Vector v1(1, 2, 3), v2(4, 5, 6);
    cout << dot(v1, v2);   // 32
}
```

> **Interview Q**: Does `friend` violate encapsulation?  
> **Answer**: It weakens encapsulation intentionally, for tightly coupled relationships (e.g., operator overloading, testing). Use sparingly.

## 6. `mutable` Keyword

```cpp
class QueryCache {
    mutable string cachedResult;    // can be modified even in const methods
    mutable bool   isCached = false;
    string         expensiveQuery() const { return "result"; }

public:
    string getResult() const {
        if (!isCached) {
            cachedResult = expensiveQuery();   // modifying mutable member in const fn
            isCached = true;
        }
        return cachedResult;
    }
};
```

> **Use case**: Logical const-ness — the observable state doesn't change (to the caller), but internal cache does.

## 7. Copy Elision & RVO (Return Value Optimisation)

```cpp
class Heavy {
public:
    Heavy()             { cout << "Default ctor\n"; }
    Heavy(const Heavy&) { cout << "Copy ctor\n"; }
    Heavy(Heavy&&)      { cout << "Move ctor\n"; }
};

Heavy createHeavy() {
    return Heavy();     // RVO: compiler constructs directly in caller's space
}

int main() {
    Heavy h = createHeavy();  // NO copy or move — RVO eliminates it!
}
// Output: Default ctor   (just one call!)
```

> **Interview Q**: What is RVO?  
> **Answer**: Return Value Optimisation — compiler constructs the returned object directly in the caller's storage, eliminating the copy/move. Mandatory in C++17.

## 9. Quick-Revision Snapshot

```
Constructors: Default | Parameterised | Copy | Move | Delegating
Initialiser list: required for const/ref members; order = declaration order
explicit: blocks implicit single-arg conversions

Destructor: virtual if class has virtual functions (or is a base)
Without virtual dtor: delete via base ptr → UB (memory leak)

Shallow copy: copies pointer (same memory — double free!)
Deep copy:    copies data (separate memory — safe)

Rule of 3: custom dtor? define copy-ctor + copy-assign too
Rule of 5: + move-ctor + move-assign (C++11)
Rule of 0: use RAII types — zero special functions needed

friend: grants external access to private; use sparingly
mutable: modifiable in const functions (cache, mutex, etc.)
RVO: compiler eliminates copy/move for returned objects
```
