# OOP Fundamentals (C++) — 10-Min Revision

Scope: four pillars of OOP, class vs object, encapsulation, abstraction, inheritance, polymorphism, abstraction vs encapsulation, overloading vs overriding, interfaces, abstract classes.

---

## Core Theory

### 1. Four Pillars of OOP
1. **Encapsulation** — bundle data + methods into a class, restrict access via `private`/`protected`
2. **Abstraction** — expose essential interface, hide implementation complexity
3. **Inheritance** — derived class acquires base class properties/behavior (IS-A relationship), enables code reuse
4. **Polymorphism** — "many forms" — static (compile-time: overloading, templates) or dynamic (runtime: virtual functions)

### 2. Class vs Object
- **Class** — blueprint/template defining data members + member functions; occupies no memory until instantiated (except static members/vtable)
- **Object** — actual instance in memory at runtime, holding real state values

### 3. Encapsulation
Wraps data + methods in a class, restricts direct external access via access specifiers.
**Why it matters:**
- Data hiding/security — prevents invalid external state mutation
- Maintainability — internal implementation can change (e.g. `vector`→`list`) without breaking consumers of the public interface
- Validation — getters/setters can enforce invariants

### 4. Abstraction
Hides implementation complexity behind a simple public contract. Achieved via:
1. Header (`.h`) vs implementation (`.cpp`) separation
2. Abstract classes with pure virtual functions (`= 0`)
3. Access specifiers — keep helpers `private`, expose simple `public` entry points

### 5. Inheritance
Derived class inherits members/functions from base class.
**Advantages:**
- Code reusability — avoid duplicating boilerplate across similar models
- Extensibility — extend via subclassing without touching tested base code (Open/Closed Principle)
- Enables polymorphic behavior via base class pointers/references

### 6. Polymorphism — Compile-time vs Runtime

| Type | Mechanism | Binding |
|---|---|---|
| Compile-time (static) | Function overloading, operator overloading, templates | Resolved at compile time |
| Runtime (dynamic) | Virtual functions + vtables, overriding | Resolved at runtime via base pointer/reference |

### 7. Abstraction vs Encapsulation

| Aspect | Abstraction | Encapsulation |
|---|---|---|
| Question answered | "What does the object do?" | "How is the object protected?" |
| Focus | Hiding implementation details | Hiding internal state/data |
| Achieved via | Abstract classes, interfaces, APIs | Access specifiers (`private`/`protected`) |
| Level | Conceptual/design | Structural/code |

### 8. Overloading vs Overriding

| | Overloading | Overriding |
|---|---|---|
| Scope | Same scope (same class) | Across inheritance (derived redefines base) |
| Requirement | Same name, different params | Same signature, base function must be `virtual` |
| Binding | Compile-time (static) | Runtime (dynamic) |

### 9. Interfaces in C++
No native `interface` keyword. Simulated via an **abstract class with only pure virtual functions + a virtual destructor**, no member variables or implemented methods — a pure contract derived classes must fully implement.

```cpp
class IPrintable {
public:
    virtual void print() const = 0;   // pure virtual
    virtual ~IPrintable() = default;  // virtual destructor
};
```

### 10. Abstract Classes
Class with at least one **pure virtual function** (`= 0`). Cannot be instantiated directly.
**When to use:**
- Define a baseline contract for a family of derived classes, preventing generic base instantiation
- Provide shared default logic alongside methods derived classes are forced to implement

## Interview Traps

1. **Forgetting virtual destructors in base/abstract classes** — `delete` on a `Base*` pointing to a `Derived` object without a `virtual` destructor in `Base` → undefined behavior + memory leak. Always declare a virtual destructor in abstract/base classes meant for polymorphic use.
2. **"`struct` can't have methods/constructors/inheritance" (wrong)** — in C++, `struct` and `class` are identical except default access: `struct` defaults to `public`, `class` defaults to `private`.
3. **"Encapsulation = private fields + getters/setters for everything" (wrong)** — blindly exposing getters/setters for every private field creates tight coupling and defeats encapsulation's purpose. True encapsulation protects domain invariants via meaningful actions, not raw property mutators.
4. **"C++ has a native `interface` keyword" (wrong)** — C++ simulates interfaces via abstract base classes with pure virtual functions; there's no dedicated keyword like Java/C#.

## Rapid-Fire Q&A

**Q: What are the four pillars of OOP?**
A: Encapsulation, abstraction, inheritance, polymorphism.

**Q: Class vs object?**
A: Class = blueprint (no memory until instantiated); object = actual instance in memory holding real state.

**Q: What is encapsulation and why does it matter?**
A: Bundling data+methods with restricted access; enables data hiding, maintainability, and validation.

**Q: What is abstraction and how is it achieved in C++?**
A: Hiding implementation complexity behind a simple interface — via header/impl separation, abstract classes with pure virtual functions, and access specifiers.

**Q: What is inheritance and its advantages?**
A: Derived class acquires base class members; gives code reuse, extensibility (Open/Closed Principle), and enables polymorphism.

**Q: Compile-time vs runtime polymorphism?**
A: Compile-time = overloading/templates, resolved at compile time. Runtime = virtual functions/vtables, resolved dynamically via base pointer/reference.

**Q: Abstraction vs encapsulation — one line?**
A: Abstraction hides implementation complexity (design-level, "what it does"); encapsulation hides internal state (code-level, "how it's protected").

**Q: Overloading vs overriding?**
A: Overloading = same scope, same name, different params, resolved at compile time. Overriding = across inheritance, same signature, `virtual`, resolved at runtime.

**Q: How does C++ implement interfaces?**
A: Abstract class with only pure virtual functions + a virtual destructor, no member variables or implemented methods.

**Q: What is an abstract class and when do you use it?**
A: A class with ≥1 pure virtual function, can't be instantiated; used to define a shared contract/baseline for derived classes, optionally with default shared logic.

**Q: Why must base classes have virtual destructors?**
A: Deleting a derived object through a base pointer without a virtual destructor causes undefined behavior/memory leaks (derived destructor never runs).

**Q: `struct` vs `class` in C++?**
A: Functionally identical except default access: `struct` = public by default, `class` = private by default.
