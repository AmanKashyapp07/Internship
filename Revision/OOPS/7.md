# OOP — Advanced Language Features (C++) — 10-Min Revision

Scope: `this` pointer, method chaining, object vs pointer vs reference, cast types (`static_cast`, `dynamic_cast`, `const_cast`, `reinterpret_cast`), `explicit`, `= default`/`= delete`, `friend`.

---

## Core Theory

### 1. `this` Pointer & Method Chaining
- **`this`** — hidden constant pointer implicitly passed to non-static member functions, holds the address of the invoking instance
- **Method chaining** — functions return `*this` (a reference to the current object), allowing calls to be linked: `logger.setLevel(DEBUG).setMessage("Error").write();`

### 2. Object vs Pointer vs Reference
- **Object** — direct instance holding its own data (stack or heap)
- **Pointer (`T*`)** — holds an address, reassignable, can be `nullptr`, supports arithmetic
- **Reference (`T&`)** — alias for an existing object, cannot be null, cannot be re-seated after init, behaves syntactically like the original

### 3. Pointer vs Reference (direct comparison)

| | Pointer | Reference |
|---|---|---|
| Nullable? | Yes | No — must refer to valid object |
| Re-seatable? | Yes | No — bound permanently at init |
| Syntax | Needs `*`/`&` explicitly | Transparent, acts like a normal variable |

### 4. Cast Types

| Cast | Purpose | Safety |
|---|---|---|
| `static_cast` | Compile-time conversions (numeric, safe upcasts) | No runtime check — fast but unsafe for downcasts |
| `dynamic_cast` | Runtime-checked downcast/cross-cast for polymorphic types (needs ≥1 virtual function) | Safe — uses RTTI; pointer cast fails to `nullptr`, reference cast throws `std::bad_cast` |
| `const_cast` | Add/remove `const`/`volatile` qualifiers | Modifying an originally-`const` object via this = undefined behavior |
| `reinterpret_cast` | Low-level bitwise reinterpretation (pointer↔int, unrelated pointer types) | Platform-dependent, high risk, avoid unless doing raw hardware/allocator work |

### 5. `explicit` Keyword
Placed on constructors to block **implicit conversions**.
```cpp
class MyString { public: explicit MyString(int size); };
// MyString str = 50;  // COMPILE ERROR (blocked implicit conversion)
MyString str(50);       // OK — explicit construction
```

### 6. `= default` and `= delete` (C++11)
- **`= default`** — explicitly request compiler-generated implementation of a special member function, even if other constructors exist
- **`= delete`** — explicitly disable a function (e.g., block copying by deleting the copy constructor/assignment)

### 7. `friend` Function / `friend class`
Grants an external function or class access to `private`/`protected` members. Useful for tightly coupled patterns (custom iterators, `operator<<` overloads) but **breaks encapsulation** — use sparingly.

---

## Interview Traps

1. **"References are just const pointers under the hood" (wrong)** — the standard doesn't mandate this implementation detail; conceptually references are aliases, and `sizeof(reference)` equals the size of the referenced type, not a pointer's size.
2. **"Use `reinterpret_cast` for polymorphic downcasts because it's faster" (wrong)** — `reinterpret_cast` bypasses all type safety and ignores vtable offsets in multiple inheritance, leading to undefined behavior/segfaults. Use `dynamic_cast` for safe polymorphic downcasts.

## Rapid-Fire Q&A

**Q: What is the `this` pointer?**
A: A hidden pointer implicitly passed to non-static member functions, pointing to the invoking object.

**Q: How does method chaining work?**
A: Each method returns `*this`, letting multiple calls be linked in one statement.

**Q: Object vs pointer vs reference?**
A: Object = direct instance. Pointer = reassignable address holder, can be null. Reference = permanent alias, can't be null or re-seated.

**Q: `static_cast` vs `dynamic_cast`?**
A: `static_cast` is compile-time, no safety check (fast, risky for downcasts); `dynamic_cast` is runtime-checked via RTTI for safe polymorphic downcasting.

**Q: `const_cast` vs `reinterpret_cast`?**
A: `const_cast` only changes const/volatile qualifiers (modifying a truly-const object is UB). `reinterpret_cast` does low-level bitwise reinterpretation between unrelated types — high risk, platform-dependent.

**Q: What does `explicit` do?**
A: Prevents a constructor from being used for implicit type conversions.

**Q: What do `= default` and `= delete` do?**
A: `= default` requests the compiler's default implementation explicitly; `= delete` disables a function entirely (e.g., to prevent copying).

**Q: What does `friend` do and what's the tradeoff?**
A: Grants external access to private/protected members — useful for tightly coupled cases (operator overloads, iterators) but weakens encapsulation.

**Q: Is a reference literally a pointer internally?**
A: Not by standard mandate — it's an alias; `sizeof` a reference equals the referenced type's size, not a pointer's size, even if some compilers implement it that way under the hood.

**Q: Why is `reinterpret_cast` dangerous for downcasting polymorphic types?**
A: It ignores vtable layout/offsets (especially under multiple inheritance), leading to undefined behavior — use `dynamic_cast` instead.
