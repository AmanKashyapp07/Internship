# OOP — Constructors & Destructors (C++) — 10-Min Revision

Scope: constructor types, copy constructor, copy assignment, move constructor, constructor delegation, why constructors can't be virtual, destructors, virtual destructors.

---

## Core Theory

### 1. Constructors — Types
Special member function, same name as class, no return type, auto-called on instantiation.
1. **Default** — no args (or all defaulted); auto-generated if none defined
2. **Parameterized** — accepts args to init state
3. **Copy** — `Type(const Type&)` — builds new object as a copy of an existing one
4. **Move (C++11)** — `Type(Type&&)` — transfers ownership of resources from an rvalue/temporary
5. **Delegating (C++11)** — one constructor calls another in the same class via initializer list

### 2. Copy Constructor
Signature: `ClassName(const ClassName& source)`. Invoked in 3 cases:
1. Direct/copy initialization — `Obj a = b;` or `Obj a(b);`
2. Pass-by-value parameter passing
3. Return-by-value (may be elided by RVO)

### 3. Copy Constructor vs Copy Assignment Operator

| | Copy Constructor | Copy Assignment (`operator=`) |
|---|---|---|
| When | New object being created | Existing object being updated |
| Cleanup needed? | No (fresh object) | Yes (release old resources first) |

```cpp
MyClass obj2 = obj1;   // copy constructor (new object)
obj3 = obj1;           // copy assignment (existing object)
```

### 4. Move Constructor
`Type(Type&& non_const_rvalue)` — steals resources from a temporary, leaving source in a valid-but-unspecified state.
- **Why introduced:** avoids expensive deep copies for temporaries (e.g. returning large `vector`/`string`); replaces heap copy with cheap pointer swap (O(1))

### 5. Constructor Delegation
One constructor calls another constructor of the same class in its initializer list, centralizing init logic.
```cpp
Player(std::string n, int h) : name(n), health(h) {}   // primary
Player(std::string n) : Player(n, 100) {}              // delegates
```

### 6. Why Constructors Can't Be Virtual
1. **Vtable unreadiness** — the vptr is set up *during* construction; before that, dynamic dispatch isn't possible
2. **Memory allocation mechanics** — compiler needs exact type/size to allocate before construction; virtual implies dynamic typing, contradicting static allocation
3. **Conceptual mismatch** — virtual functions customize behavior on an *existing* instance of unknown derived type; a constructor's job is to *create* that instance

### 7. Destructor's Role
`~ClassName()` — auto-called at end of object lifetime (scope exit or `delete`). Releases heap memory, closes files, releases locks/sockets. Foundation of **RAII**.

### 8. Why Base Class Destructors Must Be Virtual
If deleting a `Derived` object via a `Base*` pointer and `Base`'s destructor isn't virtual: only `Base`'s destructor runs, `Derived`'s never does → undefined behavior + leaked derived-owned resources.

## Interview Traps

1. **"`Obj b = a;` calls assignment operator" (wrong)** — since `b` is being *declared* on this line, it invokes the **copy constructor**, not `operator=`.
2. **Copy constructor signature `Type(Type obj)` (wrong)** — pass-by-value here requires copying `obj` into the parameter, which needs the copy constructor again → infinite recursion. Must pass by reference: `Type(const Type& obj)`.
3. **Forgetting Rule of 3/5** — if you explicitly define a destructor (usually to manage heap memory), you likely need to define/delete all five: destructor, copy ctor, copy assignment, move ctor, move assignment.
4. **Letting exceptions escape destructors** — if a destructor throws while another exception is already unwinding the stack, `std::terminate()` is called, crashing the program. Destructors should be `noexcept` (the default in modern C++).

## Rapid-Fire Q&A

**Q: Name the constructor types in C++.**
A: Default, parameterized, copy, move (C++11), delegating (C++11).

**Q: When is the copy constructor invoked?**
A: Direct/copy initialization, pass-by-value, and return-by-value (unless elided by RVO).

**Q: Copy constructor vs copy assignment operator?**
A: Copy constructor builds a brand-new object from an existing one; copy assignment updates an already-existing object, requiring cleanup of its old resources first.

**Q: What is a move constructor and why was it introduced?**
A: `Type(Type&&)` steals resources from a temporary instead of deep-copying — avoids costly heap copies, replacing them with O(1) pointer swaps.

**Q: What is constructor delegation?**
A: One constructor invokes another constructor of the same class in its initializer list, reducing duplicated init code.

**Q: Why can't constructors be virtual?**
A: The vptr isn't set up until construction runs, the compiler needs exact type/size before allocation, and conceptually a constructor creates the instance a virtual call would otherwise customize.

**Q: What does a destructor do?**
A: Cleans up resources (memory, file handles, locks, sockets) when an object's lifetime ends — core of RAII.

**Q: Why must a base class destructor be virtual for polymorphic deletion?**
A: Without it, deleting a `Derived` via a `Base*` only runs `Base`'s destructor, skipping `Derived`'s and leaking its resources — undefined behavior.

**Q: What's the danger of a copy constructor written as `Type(Type obj)`?**
A: Pass-by-value triggers the copy constructor to copy the parameter, causing infinite recursion — must use `const Type&`.

**Q: What is the Rule of 3/5?**
A: If you define one of destructor/copy ctor/copy assignment (Rule of 3), or also move ctor/move assignment (Rule of 5), you should typically define or explicitly delete all of them.

**Q: What happens if a destructor throws during stack unwinding?**
A: `std::terminate()` is called, crashing the program — hence destructors should be `noexcept`.
