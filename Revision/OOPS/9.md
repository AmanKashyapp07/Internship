# OOP Bonus (Part 2) — Storage Duration, Templates, CRTP & Advanced Idioms

Scope: object lifetime/storage duration, static vs virtual functions, exceptions in constructors, multilevel inheritance ctor/dtor order, templates vs runtime polymorphism, covariant return types, name lookup/ADL, CRTP, EBO.

---

## Core Theory

### 1. Object Lifetime vs Storage Duration
- **Lifetime** — runtime span from construction completion to destructor completion
- **Storage duration** (4 kinds):
  1. **Automatic** — local stack vars, freed at scope exit
  2. **Static** — globals/`static` vars, allocated at startup, freed at shutdown
  3. **Dynamic** — heap via `new`/`delete`
  4. **Thread-local** — `thread_local`, one instance per thread

### 2. Why Static Member Functions Can't Be Virtual
Virtual dispatch needs an instance's `vptr`. Static functions have no `this` pointer / instance context → no vptr available → dynamic resolution impossible.

### 3. Why Virtual Functions Can't Be Static
Same root cause in reverse: `virtual` fundamentally requires reading `this->vptr` at runtime; `static` functions have no `this` at all.

### 4. Constructor Throwing an Exception
1. Object is considered **never fully constructed** — its own destructor does **not** run
2. Already-constructed base/member subobjects have their destructors run in **reverse order** of construction
3. Fix: wrap raw pointers inside the constructor in RAII types (`unique_ptr`) to avoid leaks on the throw path

### 5. Constructor/Destructor Order in Multilevel Inheritance
- **Construction:** top-down, Grandparent → Parent → Child, then member initialization
- **Destruction:** exact reverse — Child → Parent → Grandparent

### 6. Compile-time Polymorphism vs Templates
- **Templates (parametric polymorphism)** — generate distinct code per instantiation at compile time, no inheritance needed
- **Runtime (subtype) polymorphism** — virtual functions + base pointers, resolved at runtime
- Templates trade runtime vtable lookup overhead for potential code bloat (multiple instantiations)

### 7. Covariant Return Types
An overriding virtual function can return a **more derived pointer/reference type** than its base version.
```cpp
class Base    { virtual Base* clone(); };
class Derived : public Base { Derived* clone() override; }; // valid — covariant
```

### 8. Name Lookup & ADL (Argument-Dependent Lookup)
- **Name lookup** — compiler resolves an identifier to its declaration in scope
- **ADL (Koenig Lookup)** — for unqualified function calls, compiler also searches the **namespaces of the arguments' types**, not just local scope — this is why `std::cout << obj;` finds a non-member `operator<<` without full qualification

### 9. CRTP (Curiously Recurring Template Pattern)
`class Derived : public Base<Derived>` — achieves **static polymorphism** without vptr/vtable runtime cost. Base casts `this` to `Derived*` via `static_cast` at compile time.
```cpp
template <typename Derived>
class Base {
public:
    void interface() { static_cast<Derived*>(this)->implementation(); }
};
class Derived : public Base<Derived> {
public:
    void implementation() { /* resolved statically */ }
};
```

### 10. Empty Base Optimization (EBO) & Empty Class Size
- **Empty class size rule** — `sizeof(EmptyClass) == 1` minimum, so distinct instances get unique addresses
- **EBO** — an empty base class inherited by a derived class can take **0 bytes** in the derived object (compiler optimization), avoiding padding bloat
- C++20's `[[no_unique_address]]` extends similar savings to empty data members

---

## Interview Traps

1. **"CRTP uses runtime polymorphism" (wrong)** — CRTP is fully resolved at compile time via template instantiation; zero vptr/vtable involved, unlike virtual overriding.
2. **"An empty class is 0 bytes" (wrong)** — standalone, it's always ≥1 byte (for unique addressing); it only becomes 0 bytes when optimized away as an empty *base* via EBO.

## Rapid-Fire Q&A

**Q: What are the 4 storage durations in C++?**
A: Automatic (stack), static (global/static), dynamic (heap), thread-local.

**Q: Why can't static member functions be virtual?**
A: They have no `this` pointer/instance vptr, so dynamic dispatch has nothing to resolve against.

**Q: What happens if a constructor throws mid-execution?**
A: The object itself isn't considered constructed (no destructor call for it), but already-built base/member subobjects get destructed in reverse order.

**Q: Constructor/destructor order in multilevel inheritance?**
A: Construction top-down (Grandparent→Parent→Child); destruction bottom-up in exact reverse.

**Q: How do templates differ from runtime polymorphism?**
A: Templates generate separate code per type at compile time (no vtable, but code bloat risk); runtime polymorphism uses virtual dispatch with base pointers.

**Q: What is a covariant return type?**
A: An override returning a more-derived pointer/reference type than the base version specified — legal in C++.

**Q: What is ADL?**
A: Argument-Dependent Lookup — compiler also searches argument types' namespaces for unqualified function calls, e.g. how `cout << obj` finds `operator<<` without full qualification.

**Q: What is CRTP and why use it?**
A: A class inherits from a template base parameterized on itself (`Derived : Base<Derived>`), enabling compile-time ("static") polymorphism without virtual-call overhead.

**Q: What is the empty class size rule?**
A: An empty class must be at least 1 byte so array elements/instances get unique addresses.

**Q: What is Empty Base Optimization (EBO)?**
A: When an empty class is inherited as a base, the compiler can make it take 0 bytes in the derived object, avoiding wasted padding.
