## 1. Core Theory & Architecture

### 1.1 OSI Model vs. TCP/IP Model

The **OSI (Open Systems Interconnection) model** is a 7-layer theoretical reference framework used for reasoning, designing, and troubleshooting networks. The **TCP/IP model** (4-5 layers) is the practical, streamlined architecture actually implemented in operating systems (Linux/Windows network stacks) and internet hardware.

| OSI Layer | PDU (Data Unit) | Core Responsibility | Key Protocols / Standards | Network Device |
|---|---|---|---|---|
| **7. Application** | Data / Message | User interaction & app-level protocols | HTTP, HTTPS, DNS, SSH, FTP, SMTP, DHCP | Gateway, Reverse Proxy |
| **6. Presentation** | Data | Data formatting, encryption, compression | TLS/SSL, JSON, ASCII, JPEG | — |
| **5. Session** | Data | Manages sessions, dialogues & connections | Sockets, RPC, NetBIOS | — |
| **4. Transport** | **Segment** (TCP) / **Datagram** (UDP) | End-to-end delivery, port multiplexing, reliability | TCP, UDP | L4 Load Balancer, Firewall |
| **3. Network** | **Packet** | Logical addressing & routing across networks | IP (IPv4/IPv6), ICMP, ARP* | **Router**, L3 Switch |
| **2. Data Link** | **Frame** | Node-to-node hop, physical addressing (MAC), framing, error detection | Ethernet (802.3), Wi-Fi (802.11), MAC | **Switch**, Bridge, NIC |
| **1. Physical** | **Bits** | Transmission of raw electrical/optical/radio signals over medium | Cables, Fiber, RJ45, Radio | **Hub**, Repeater |

*\*Note on ARP: Operates between Layer 2 and Layer 3 (translates L3 IP addresses to L2 MAC addresses).*

#### TCP/IP 4-Layer Mapping:
1. **Application Layer** (combines OSI layers 5, 6, 7) — HTTP, DNS, SSH, TLS.
2. **Transport Layer** (maps to OSI layer 4) — TCP, UDP.
3. **Internet Layer** (maps to OSI layer 3) — IPv4, IPv6, ICMP.
4. **Network Access / Link Layer** (combines OSI layers 1, 2) — Ethernet, Wi-Fi, MAC.

### 1.2 Encapsulation & Decapsulation

As data travels down the stack, each layer wraps the payload from the layer above with its own header (and trailer at L2). On the receiving host, the reverse occurs (**Decapsulation**):

```
Application Data
      │
      ▼
[ TCP Header | Application Data ]                      ➔ Segment (Layer 4 - Transport)
      │
      ▼
[ IP Header | TCP Header | Application Data ]          ➔ Packet (Layer 3 - Network)
      │
      ▼
[ Ethernet Header | IP Header | TCP Header | Data | FCS Trailer ] ➔ Frame (Layer 2 - Data Link)
      │
      ▼
010101101010010101011101001010100101011010100101010101 ➔ Bits (Layer 1 - Physical)
```

- Each layer treats data passed to it as an **opaque payload** and inspects only its own header.
- The destination MAC changes hop-by-hop; the source and destination IP addresses remain constant end-to-end across the Internet (unless NAT is involved).

### 1.3 Key Devices: Hub vs. Switch vs. Router

| Device | Layer | How It Forwards Traffic | Broadcast Domain | Collision Domain | Duplex Mode |
|---|---|---|---|---|---|
| **Hub** | **L1** (Physical) | Dumb device: repeats incoming bits to **all** ports simultaneously | 1 single domain | 1 shared domain (frequent collisions) | Half-Duplex |
| **Switch** | **L2** (Data Link) | Smart device: inspects destination **MAC address** using an internal MAC address table; forwards frame only to matching port | 1 single domain (forwards broadcasts) | **Every port is its own collision domain** | Full-Duplex |
| **Router** | **L3** (Network) | Inspects destination **IP address** using a routing table; forwards packets between different subnets/networks | **Breaks broadcast domains** (drops broadcasts by default) | Every port is its own collision domain | Full-Duplex |

- **Collision Domain**: A network segment where packets can collide if transmitted simultaneously. Switches eliminate collisions by giving each port an independent collision domain.
- **Broadcast Domain**: The scope in which any broadcast packet (`FF:FF:FF:FF:FF:FF`) sent by a host will be received by all other devices. Only routers (or VLANs on L3 switches) divide broadcast domains.
- **Half-Duplex vs. Full-Duplex**:
  - **Half-Duplex**: Data flows in both directions, but only one direction at a time (like a walkie-talkie). Prone to collisions.
  - **Full-Duplex**: Data transmits and receives simultaneously on separate transmit/receive channels (like a telephone call or modern Ethernet).

### 1.4 IP Addressing, Subnetting & CIDR

- **IPv4**: 32-bit address, written as 4 decimal octets separated by dots (e.g., `192.168.1.10`). Total address space $\approx 2^{32} \approx 4.3\text{ billion}$ addresses.
- **IPv6**: 128-bit address, written as 8 groups of 4 hexadecimal digits separated by colons (e.g., `2001:0db8:85a3:0000:0000:8a2e:0370:7334`). Created to solve IPv4 exhaustion, with built-in auto-configuration (SLAAC) and simplified headers.
- **Subnetting**: Logically partitioning a single physical network into smaller sub-networks using a **Subnet Mask**.
  - **Network ID**: Bits representing the network/prefix.
  - **Host ID**: Bits representing individual device addresses within that network.
  - **CIDR Notation** (Classless Inter-Domain Routing): Written as `/prefix_length` (e.g. `192.168.1.0/24`).
    - `/24` means the first 24 bits are Network ID ($255.255.255.0$), leaving $32 - 24 = 8$ bits for hosts.
    - Total addresses $= 2^8 = 256$.
    - **Usable addresses** $= 256 - 2 = 254$ (First address is Network ID: `192.168.1.0`, last address is Broadcast ID: `192.168.1.255`).
  - **Why subnet?**
    1. Shrinks broadcast domains (stops broadcast storms).
    2. Enforces network security boundaries and firewall rules.
    3. Prevents IPv4 address waste.

### 1.5 Public vs. Private IP & NAT (Network Address Translation)

#### Private IP Ranges (RFC 1918)
Reserved strictly for internal local networks; routers on the public Internet will immediately drop them:
- **Class A**: `10.0.0.0 – 10.255.255.255` (`10.0.0.0/8`, ~16.7M hosts)
- **Class B**: `172.16.0.0 – 172.31.255.255` (`172.16.0.0/12`, ~1M hosts)
- **Class C**: `192.168.0.0 – 192.168.255.255` (`192.168.0.0/16`, ~65k hosts — standard home/office routers)

#### Why NAT Exists:
1. **IPv4 conservation**: Millions of devices inside homes and enterprises share a single publicly routable IP address.
2. **Security & Obfuscation**: Internal topologies and private host addresses are hidden from direct outside exposure.

#### How NAT Works (PAT / NAT Overload / NAPT):
A home or enterprise router modifies packet headers on the fly:
1. Device A (`192.168.1.15:5000`) sends an outbound packet to Google (`142.250.190.46:443`).
2. The router rewrites the source IP with its own public IP (`203.0.113.5`) and assigns an ephemeral port (`40001`).
3. The router logs this in its **NAT Translation Table**:
   ```
   Internal (Private) IP:Port        External (Public) IP:Port
   192.168.1.15:5000         <--->   203.0.113.5:40001
   192.168.1.20:5000         <--->   203.0.113.5:40002
   ```
4. When Google's response arrives at `203.0.113.5:40001`, the router consults the table, rewrites the destination back to `192.168.1.15:5000`, and forwards it to Device A.

### 1.6 MAC Address vs. IP Address

| Feature | MAC Address (Physical) | IP Address (Logical) |
|---|---|---|
| **Layer** | Layer 2 (Data Link) | Layer 3 (Network) |
| **Scope** | Local network segment (hop-by-hop) | Global / End-to-End routable |
| **Assignment** | Burned into NIC hardware by manufacturer | Dynamically assigned via DHCP or statically configured |
| **Format** | 48 bits (6 bytes), hex (e.g., `00:1A:2B:3C:4D:5E`) | 32 bits (IPv4) or 128 bits (IPv6) |
| **Portability** | Fixed to hardware | Changes when moving between networks |
| **Routing Behavior** | Rewritten at every router hop | Preserved end-to-end across internet hops |

### 1.7 Essential Protocols: ARP, DHCP & ICMP

#### 1. ARP (Address Resolution Protocol)
Resolves a known Layer 3 IP address to an unknown Layer 2 MAC address on the local network segment.
- **Problem**: Host A wants to send an IP packet to `192.168.1.50`, but Ethernet cards require a destination MAC address to build an Ethernet frame.
- **Workflow**:
  1. Host A checks its local **ARP Cache / Table**.
  2. If absent, Host A sends an **ARP Request** broadcast (`FF:FF:FF:FF:FF:FF`): *"Who has IP 192.168.1.50? Tell 192.168.1.10."*
  3. Every device on the LAN processes the broadcast, but only the host with `192.168.1.50` responds with a unicast **ARP Reply**: *"I am 192.168.1.50, my MAC is 00:1A:2B:3C:4D:5E."*
  4. Host A caches this entry in its ARP cache and sends the queued frame.

#### 2. DHCP (Dynamic Host Configuration Protocol) — The DORA Process
Automatically assigns IP configuration to devices when joining a network via 4 UDP messages (Server Port 67, Client Port 68):
```
Client                                                  DHCP Server
  │                                                          │
  │─── 1. Discover (Broadcast: "Any DHCP server here?") ────▶│
  │                                                          │
  │◀── 2. Offer (Unicast/Broadcast: "Use 192.168.1.25") ─────│
  │                                                          │
  │─── 3. Request (Broadcast: "I request 192.168.1.25") ────▶│
  │                                                          │
  │◀── 4. Acknowledge (Unicast: "Lease confirmed for 24h") ──│
```
- **Configuration Delivered**:
  1. Assigned Private IP address (e.g. `192.168.1.25`)
  2. Subnet Mask (e.g. `255.255.255.0`)
  3. Default Gateway IP (Router address, e.g. `192.168.1.1`)
  4. Primary and Secondary DNS Server IPs (e.g. `8.8.8.8`, `1.1.1.1`)

#### 3. ICMP (Internet Control Message Protocol) & Ping
- Operates at **Layer 3 (Network Layer)** alongside IP.
- Diagnostic and error-reporting protocol (used for error notifications like *Host Unreachable*, *TTL Expired*).
- **`ping`**: Sends an `ICMP Echo Request` (Type 8) and waits for an `ICMP Echo Reply` (Type 0).
- **Why `ping` does not use a port**: Ports belong to Layer 4 (TCP/UDP) to multiplex applications. ICMP operates directly over IP at Layer 3 to test OS-to-OS network reachability.
- **TTL (Time to Live)**: An 8-bit field in the IPv4 header (called *Hop Limit* in IPv6). Decremented by 1 at every router hop. If it reaches 0, the router discards the packet and sends an `ICMP Time Exceeded` message back to the sender, preventing infinite routing loops.

## 2. Real-World Scenarios & Architectural Deep-Dives

### Scenario 1: What happens when your laptop connects to a Wi-Fi network?
1. **Wi-Fi Association (Layer 2)**:
   - Laptop scans for SSIDs, associates with the Access Point (AP), and performs the WPA2/WPA3 4-way authentication handshake to establish encryption keys over radio frequencies (802.11).
2. **IP Configuration via DHCP DORA (Layer 7 over UDP 67/68)**:
   - **Discover**: Client broadcasts: *"Who can give me an IP?"*
   - **Offer**: Router/DHCP server offers an available IP (`192.168.1.25`).
   - **Request**: Client confirms acceptance of the offered lease.
   - **Acknowledge**: Server locks in the lease and returns:
     - Client IP: `192.168.1.25`
     - Subnet Mask: `255.255.255.0`
     - Default Gateway: `192.168.1.1`
     - DNS Servers: `1.1.1.1`, `8.8.8.8`
3. **Gratuitous ARP**: Laptop broadcasts an ARP request for its newly assigned IP to verify no duplicate IP address exists on the local network.

---

### Scenario 2: Host A communicates with Host B (Same LAN vs. Different LAN)

#### Case 1: Same Subnet (e.g. `192.168.1.10/24` to `192.168.1.20/24`)
1. Host A applies its subnet mask (`255.255.255.0`) to both its IP and destination IP. Both resolve to `192.168.1.0`. Host A realizes Host B is **local**.
2. Host A checks its ARP cache for Host B's MAC address.
3. If absent, Host A broadcasts an **ARP Request**. Host B replies with its MAC address.
4. Host A sends the Ethernet frame directly through the **Layer 2 Switch**.
5. The router/default gateway is **never involved**.

#### Case 2: Different Subnet / Internet (e.g. `192.168.1.10/24` to `8.8.8.8`)
1. Host A applies its subnet mask and discovers the destination IP is **remote**.
2. Host A cannot send directly to `8.8.8.8`; it must forward the packet to its **Default Gateway (Router)**.
3. Host A resolves the Router's IP (`192.168.1.1`) to its MAC address via ARP.
4. Host A constructs an Ethernet frame:
   - **Destination MAC**: Router's MAC address
   - **Destination IP**: `8.8.8.8` (remains unchanged)
5. The router receives the frame, strips the L2 Ethernet header, inspects the L3 destination IP (`8.8.8.8`), decrements TTL by 1, encapsulates the packet into a new L2 frame with the next-hop router's MAC, and routes it across the WAN/ISP.

---

### Scenario 3: How NAT Allows Multiple Devices to Share One Public IP
- Three smartphones and two laptops inside a house all have private IPs (`192.168.1.10` through `192.168.1.14`).
- All 5 devices stream YouTube videos simultaneously through a single ISP public IP (`203.0.113.88`).
- The router tracks outbound connections using **Port Address Translation (PAT)**:
  - Phone 1: `192.168.1.10:49152` ➔ Rewritten to `203.0.113.88:30001`
  - Laptop 1: `192.168.1.11:49152` ➔ Rewritten to `203.0.113.88:30002`
- Even though both client devices used the same local port (`49152`), the router assigned distinct public ports (`30001` and `30002`). When packets return from Google, the destination port informs the router exactly which internal private device should receive each stream.

## 3. Interview Traps & Common Misconceptions

1. **"The OSI model is literally implemented in the Linux kernel." (WRONG)**
   - *Correction*: The internet is built entirely on the **TCP/IP model**. OSI is a conceptual reference framework. TCP/IP collapses Presentation and Session layers into the Application layer, and Data Link and Physical layers into the Network Access layer.
2. **"MAC addresses stay the same as a packet traverses the Internet." (WRONG)**
   - *Correction*: **MAC addresses change at every single router hop**. Each router strips the old frame, consults its routing table, and creates a new Ethernet frame with its own MAC as source and the next hop's MAC as destination. The **IP address remains constant end-to-end** (unless modified by NAT).
3. **"Switches route packets based on IP addresses." (WRONG)**
   - *Correction*: Standard L2 switches have no concept of IP addresses; they operate exclusively on Layer 2 MAC addresses. Only Routers and Layer 3 switches make forwarding decisions based on IP addresses.
4. **"Private RFC 1918 IPs can be routed directly across the public Internet." (WRONG)**
   - *Correction*: ISPs configure border routers to drop any packet containing a private RFC 1918 destination IP. Public Internet communication requires NAT to translate to a globally routable public IP.
5. **"Subnetting is only used to count IP addresses; it has no security impact." (WRONG)**
   - *Correction*: Subnetting partitions broadcast domains, isolates traffic between sensitive subnets (e.g. database subnets vs. public DMZs), and allows strict Layer 3/4 firewall access control lists (ACLs) to be applied.
6. **"Ping uses UDP port 53 or port 7." (WRONG)**
   - *Correction*: Ping uses ICMP directly over IP at Layer 3. It does not use transport-layer ports at all.

## 4. High-Yield Interview Q&A & Flashcards

### Q1: What is the primary difference between the OSI and TCP/IP models?
**Answer**: OSI is a 7-layer theoretical reference framework; TCP/IP is a practical 4-layer architecture implemented on the real Internet. TCP/IP collapses OSI's Physical and Data Link layers into the Network Access/Link layer, and merges Session, Presentation, and Application layers into a single Application layer.

### Q2: What are the Protocol Data Units (PDUs) at each layer?
**Answer**:
- Layer 1 (Physical): **Bits**
- Layer 2 (Data Link): **Frames**
- Layer 3 (Network): **Packets**
- Layer 4 (Transport): **Segments** (TCP) / **Datagrams** (UDP)
- Layer 7 (Application): **Data / Messages**

### Q3: What is the difference between a Hub, a Switch, and a Router?
**Answer**: A **Hub** (L1) broadcasts incoming bits to all connected ports without intelligence. A **Switch** (L2) inspects MAC addresses to deliver frames exclusively to the specific destination port. A **Router** (L3) inspects IP addresses to route packets across different networks and subnets.

### Q4: What is a Collision Domain vs. a Broadcast Domain?
**Answer**: A **collision domain** is a network segment where simultaneous transmissions cause packet collisions (switches create a separate collision domain per port). A **broadcast domain** is the scope in which all devices receive any broadcast frame sent (`FF:FF:FF:FF:FF:FF`). Switches forward broadcasts; only routers break broadcast domains.

### Q5: What is the difference between Half-Duplex and Full-Duplex?
**Answer**: In **half-duplex**, data transmits in both directions, but only one direction at a time (like walkie-talkies; shared collision domain). In **full-duplex**, data transmits in both directions simultaneously over dedicated transmit/receive channels (modern Ethernet).

### Q6: What is the difference between a MAC address and an IP address?
**Answer**: A MAC address is a 48-bit physical hardware address burned into the NIC, used for local hop-by-hop frame delivery within a LAN. An IP address is a 32-bit (IPv4) or 128-bit (IPv6) logical address assigned dynamically or statically, used for global end-to-end packet routing across networks.

### Q7: What is ARP and how does it work?
**Answer**: Address Resolution Protocol translates a known Layer 3 IP address to an unknown Layer 2 MAC address on a local network. A device broadcasts an ARP Request (`Who has IP X?`); the owner replies with a unicast ARP Reply containing its MAC address, which the sender caches in its ARP table.

### Q8: What is DHCP and explain the DORA process?
**Answer**: DHCP automatically assigns dynamic IP configurations to devices joining a network via 4 UDP packets:
- **Discover**: Client broadcasts looking for a DHCP server.
- **Offer**: Server offers an available IP address.
- **Request**: Client formally requests to lease the offered IP.
- **Acknowledge**: Server confirms the lease, providing IP, subnet mask, default gateway, and DNS servers.

### Q9: What is NAT (Network Address Translation) and why is it needed?
**Answer**: NAT allows an entire private local network (RFC 1918 IPs) to share a single public IP address when accessing the Internet. It was invented to mitigate IPv4 exhaustion and adds security by hiding internal network topologies.

### Q10: What is a Subnet and Subnet Mask?
**Answer**: A subnet is a logical division of an IP network. A subnet mask (e.g. `255.255.255.0` or `/24`) is a bitmask separating the IP address into the **Network ID** (routing prefix) and the **Host ID** (individual device identifier).

### Q11: What are the reserved Private IP ranges?
**Answer**: Under RFC 1918:
- **Class A**: `10.0.0.0 – 10.255.255.255` (`/8`)
- **Class B**: `172.16.0.0 – 172.31.255.255` (`/12`)
- **Class C**: `192.168.0.0 – 192.168.255.255` (`/16`)

### Q12: What is ICMP and how does `ping` use it?
**Answer**: ICMP is a Layer 3 network diagnostic and error-reporting protocol. The `ping` utility sends an `ICMP Echo Request` (Type 8) to test destination reachability and measures round-trip time via `ICMP Echo Reply` (Type 0). It operates directly over IP without TCP/UDP port numbers.

### Q13: What is TTL (Time to Live) in an IP packet?
**Answer**: TTL is an 8-bit field in IPv4 (Hop Limit in IPv6) decremented by 1 at every router hop. When TTL hits 0, the packet is discarded and an `ICMP Time Exceeded` message is returned to the sender, preventing infinite routing loops.
