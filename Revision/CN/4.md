# Top 40 CN Interview Questions — Master Interview Prep

> **Interview Mindset**: In technical interviews, avoid rambling or reciting purely academic definitions. Deliver the **core thesis first**, follow up with **concrete technical specifics** (layers, protocols, headers, or state flags), and finish with a **practical design or production insight**.

---

## 1. Models & Addressing

### 1. What is the OSI model? Name its layers.
- **Direct Answer**: The Open Systems Interconnection (OSI) model is a 7-layer conceptual reference framework established by ISO to standardize telecommunication functions without regard to internal hardware technology.
- **The 7 Layers (Top to Bottom)**:
  1. **Layer 7 — Application**: User-facing network services (HTTP, DNS, SSH, FTP).
  2. **Layer 6 — Presentation**: Data formatting, character encoding, compression, and encryption/TLS.
  3. **Layer 5 — Session**: Manages dialogues, connections, and sessions between applications (Sockets, RPC).
  4. **Layer 4 — Transport**: End-to-end communication, segmentation, flow control, and reliability (TCP, UDP).
  5. **Layer 3 — Network**: Logical addressing, packet forwarding, and path selection across subnets (IPv4, IPv6, ICMP, Routers).
  6. **Layer 2 — Data Link**: Physical addressing, framing, hop-by-hop delivery, and media access control (Ethernet, MAC, Switches).
  7. **Layer 1 — Physical**: Transmission of raw electrical, radio, or optical bitstreams over hardware media (Cables, Hubs, RJ45).
- **Pro-Tip**: Use the mnemonic *"All People Seem To Need Data Processing"* (L7 ➔ L1) or *"Please Do Not Throw Sausage Pizza Away"* (L1 ➔ L7).

---

### 2. Why do we use the TCP/IP model instead of OSI in practice?
- **Direct Answer**: The TCP/IP model is a pragmatic, protocol-first architecture implemented directly in real operating system kernels (e.g. the Linux network stack) and internet hardware, whereas OSI was designed theoretically by committee prior to real-world deployment.
- **Architectural Differences**:
  - TCP/IP condenses OSI's top three layers (Session, Presentation, Application) into a single **Application Layer**.
  - TCP/IP condenses OSI's bottom two layers (Physical, Data Link) into a single **Network Access / Link Layer**.
- **Real-World Rationale**: Real-world operating systems manage Layer 3 (IP) and Layer 4 (TCP/UDP) inside the OS kernel, while session state and serialization/formatting are handled inside user-space application code, making OSI's layers 5 and 6 redundant in production stacks.

---

### 3. What happens during encapsulation and decapsulation?
- **Direct Answer**: **Encapsulation** occurs when data moves down the protocol stack from the application layer to the physical layer. Each subsequent layer wraps the payload received from the layer above with its own protocol header (and an error-detecting trailer at Layer 2).
- **Data Unit Progression (PDU)**:
  - Application Data ➔ Wrapped in TCP/UDP header ➔ **Segment / Datagram** (Layer 4)
  - Segment ➔ Wrapped in IP header (Source/Destination IP) ➔ **Packet** (Layer 3)
  - Packet ➔ Wrapped in Ethernet header (Source/Destination MAC) + FCS trailer ➔ **Frame** (Layer 2)
  - Frame ➔ Converted to electrical/optical signals ➔ **Bits** (Layer 1)
- **Decapsulation**: The receiving host moves in reverse: stripping headers layer-by-layer, verifying checksums, and passing only the inner payload up the stack.
- **Key Insight**: Each layer treats upper layers as an **opaque payload**—a switch inspects only Layer 2; a router inspects only Layer 3.

---

### 4. What is the difference between IPv4 and IPv6?
- **Direct Answer**: IPv4 uses 32-bit addresses (~4.29 billion total), written in decimal dotted-quad notation (e.g. `192.168.1.1`), and is completely exhausted. IPv6 uses 128-bit addresses ($3.4 \times 10^{38}$ total), written as 8 hexadecimal quartets (e.g. `2001:0db8::1`), providing practically infinite address space.
- **Key Technical Distinctions**:
  1. **Header Simplicity**: IPv4 headers are variable length (20–60 bytes) with checksums and fragmentation fields. IPv6 has a streamlined, fixed 40-byte base header with no checksum (relying on L2 and L4 integrity), improving router packet-processing throughput.
  2. **Fragmentation**: In IPv4, intermediate routers can fragment packets. In IPv6, routers never fragment—path MTU discovery is performed, and only the sending host fragments.
  3. **Auto-Configuration & NAT**: IPv4 relies on DHCP and NAT; IPv6 natively supports SLAAC (Stateless Address Autoconfiguration) and restores true end-to-end IP connectivity without NAT.

---

### 5. What is a MAC address and how does it differ from an IP address?
- **Direct Answer**: A MAC address is a 48-bit physical hardware identifier burned permanently into a Network Interface Card (NIC) for local Layer 2 hop-by-hop communication. An IP address is a 32-bit (v4) or 128-bit (v6) logical software address assigned dynamically or statically for global Layer 3 end-to-end routing.
- **Comparison Points**:
  - **Scope**: MAC addresses operate strictly within a single local broadcast domain (LAN). IP addresses are globally routable across networks.
  - **Routing Behavior**: The destination MAC address is stripped and **rewritten at every router hop** to match the next-hop interface. The destination IP address **remains unchanged end-to-end** across the Internet.
- **Analogy**: A MAC address is your government Social Security / National ID number (identifies you physically). An IP address is your current postal street address (tells the world where to deliver your mail).

---

### 6. What is subnetting and why is it used?
- **Direct Answer**: Subnetting is the practice of partitioning a single physical network into multiple smaller, logically distinct sub-networks by borrowing bits from the Host ID portion of an IP address to expand the Network ID using a **Subnet Mask** (or CIDR prefix).
- **Core Motivations**:
  1. **Shrinks Broadcast Domains**: Broadcast packets (`FF:FF:FF:FF:FF:FF`) are confined within the subnet, preventing network-wide broadcast storms.
  2. **Enhances Security & Isolation**: Enables network engineers to establish firewall zones and Access Control Lists (ACLs) between departments (e.g., isolating production database subnets from public DMZ subnets).
  3. **Conserves IP Allocation**: Avoids wasting massive blocks of IPv4 addresses (e.g., allocating a `/30` subnet with 2 usable IPs for point-to-point router links).

---

### 7. What is NAT and why is it needed?
- **Direct Answer**: Network Address Translation (NAT) is a technique used by routers to modify source or destination IP addresses (and ports) in packet headers while in transit, enabling an entire private network to communicate over the public Internet using a single shared public IP.
- **Why It Is Needed**:
  1. **Mitigated IPv4 Exhaustion**: Without NAT / PAT (Port Address Translation), the public IPv4 space would have collapsed decades ago.
  2. **Security & Topology Obfuscation**: Private hosts (using RFC 1918 addresses) are shielded from direct inbound internet scans because internal IPs cannot be addressed directly from the public Internet.
- **How It Operates**: The router maintains a **NAT Translation Table** mapping `{Private IP : Internal Port}` to `{Public IP : Ephemeral External Port}`, transparently translating bidirectional packets.

---

### 8. What is ARP and how does it work?
- **Direct Answer**: Address Resolution Protocol (ARP) resolves a known Layer 3 logical IP address into an unknown Layer 2 physical MAC address on the same local network segment.
- **Step-by-Step Flow**:
  1. Host A checks its local **ARP Table / Cache**.
  2. If missing, Host A broadcasts an **ARP Request** frame to MAC `FF:FF:FF:FF:FF:FF`: *"Who has IP 192.168.1.50? Tell 192.168.1.10."*
  3. Every host on the switch inspects the frame, but only the host configured with `192.168.1.50` responds with a unicast **ARP Reply**: *"I am 192.168.1.50, my MAC is 00:1A:2B:3C:4D:5E."*
  4. Host A saves this mapping into its ARP cache and transmits the queued IP packet inside an Ethernet frame.

---

### 9. What is the difference between a Hub, a Switch, and a Router?
- **Direct Answer**:
  - **Hub (Layer 1 - Physical)**: An unmanaged passive device. It repeats any incoming electrical signal to **all other ports**. It has 1 shared collision domain and 1 broadcast domain, operating in half-duplex.
  - **Switch (Layer 2 - Data Link)**: An active intelligent device. It learns MAC addresses and inspects incoming frames, forwarding them exclusively to the physical port connected to the destination device. **Every port is an independent collision domain**, operating in full-duplex.
  - **Router (Layer 3 - Network)**: An internetworking device that inspects Layer 3 IP addresses. It routes packets across different subnets and WANs according to routing tables and **breaks broadcast domains**.

---

### 10. What is the difference between a Public and a Private IP address?
- **Direct Answer**: Public IP addresses are globally unique and routable across the public Internet, assigned by IANA/ISPs. Private IP addresses are non-routable on the Internet, reserved under **RFC 1918** for internal private networks, and dropped immediately by border routers if exposed publicly.
- **RFC 1918 Private Ranges**:
  - **Class A**: `10.0.0.0/8` (`10.0.0.0` – `10.255.255.255`)
  - **Class B**: `172.16.0.0/12` (`172.16.0.0` – `172.31.255.255`)
  - **Class C**: `192.168.0.0/16` (`192.168.0.0` – `192.168.255.255`)
- **Key Distinction**: Private devices can access the public Internet only through a NAT-enabled gateway.

## 2. Transport Layer

### 11. TCP vs. UDP — What are the key architectural differences?
- **Direct Answer**: TCP is connection-oriented, highly reliable, and guarantees in-order packet delivery with flow and congestion control at the cost of higher latency and header overhead. UDP is connectionless, lightweight, and best-effort without delivery guarantees, prioritizing low latency and real-time performance.
- **Technical Checklist**:
  - **Handshake**: TCP requires a 3-way handshake; UDP has 0 handshake latency.
  - **Header Size**: TCP is 20–60 bytes; UDP is a fixed 8 bytes.
  - **Reliability**: TCP uses sequence numbers, cumulative ACKs, and timeouts for retransmission; UDP drops corrupted or lost packets silently.
  - **Transmission Mode**: TCP is strictly byte-stream unicast; UDP supports unicast, multicast, and broadcast.

---

### 12. Explain the TCP Three-Way Handshake.
- **Direct Answer**: The TCP 3-way handshake synchronizes Initial Sequence Numbers ($ISN$) and establishes socket buffers on both endpoints before application data moves.
- **Step-by-Step Flow**:
  1. **Client ➔ Server: `SYN (seq = x)`**: Client selects a random Initial Sequence Number ($x$) and transitions to `SYN_SENT`.
  2. **Server ➔ Client: `SYN-ACK (seq = y, ack = x + 1)`**: Server acknowledges the client's sequence number ($x + 1$) and provides its own random sequence number ($y$). Transitions to `SYN_RCVD`.
  3. **Client ➔ Server: `ACK (ack = y + 1)`**: Client acknowledges the server's sequence ($y + 1$). Both endpoints move to `ESTABLISHED`.
- **Why Not a 2-Way Handshake?**:
  - A 2-way handshake only verifies client-to-server delivery. The client would have no way to confirm receipt of the server's sequence number ($y$).
  - Stray or delayed duplicate `SYN` packets from dead sessions arriving at the server would force it to allocate memory for phantom connections without client confirmation.

---

### 13. Why does TCP connection termination take 4 steps instead of 3?
- **Direct Answer**: TCP is a **full-duplex** protocol—meaning data can flow independently in both directions simultaneously. Each transmission direction must therefore be closed independently by its respective sender.
- **Step-by-Step Flow**:
  1. Client sends `FIN` (*"I have completed transmitting data"*).
  2. Server sends `ACK` (*"Acknowledged. I enter half-close state; I may still have remaining buffered data to send you"*).
  3. Once the server finishes sending all remaining data, it sends its own `FIN`.
  4. Client sends the final `ACK` and enters `TIME_WAIT`.
- **Key Insight**: Because the server may still have buffered data to flush after the client initiates a close, steps 2 and 3 cannot be unconditionally combined into a single packet.

---

### 14. What is TCP Flow Control and how is it implemented?
- **Direct Answer**: Flow control is an end-to-end mechanism that prevents a fast sender from overwhelming a slow receiver's memory buffer.
- **Implementation (Sliding Window)**:
  - The receiver advertises its currently available buffer capacity in every TCP ACK packet using the **Receive Window (`rwnd`)** header field.
  - The sender is restricted to sending no more unacknowledged bytes than the advertised `rwnd`.
  - If `rwnd` drops to 0 (**Zero Window**), the sender stops transmitting data and initiates a persist timer, sending periodic 1-byte **Zero Window Probes** to detect when receiver buffer space frees up.

---

### 15. What is TCP Congestion Control? Name standard algorithms.
- **Direct Answer**: While flow control protects the receiving endpoint, congestion control prevents the sender from overwhelming the **intermediate network links and routers**.
- **Core Phases**:
  1. **Slow Start**: Begins with a small Congestion Window ($cwnd = 1–10\text{ MSS}$). For every ACK received, $cwnd$ increments by 1 MSS ($cwnd$ doubles every RTT—exponential growth) until it reaches `ssthresh`.
  2. **Congestion Avoidance**: Above `ssthresh`, $cwnd$ grows linearly by $\approx 1\text{ MSS}$ per RTT (Additive Increase).
  3. **Fast Retransmit & Fast Recovery**: Upon receiving **3 duplicate ACKs**, TCP immediately retransmits the missing segment without waiting for the slow retransmission timer (RTO) to expire and halves $cwnd$ (Multiplicative Decrease — AIMD).
- **Popular Algorithms**:
  - **Reno**: Classic loss-based AIMD.
  - **Cubic**: Default in Linux/macOS; uses a cubic mathematical curve to scale window size aggressively on high-bandwidth, high-latency links.
  - **BBR (Bottleneck Bandwidth and RTT)**: Developed by Google; model-based, measuring actual bottleneck bandwidth rather than relying on packet loss as a proxy for congestion.

---

### 16. What uniquely identifies a TCP connection?
- **Direct Answer**: A TCP connection is uniquely defined across the entire operating system by the **4-Tuple**:
  $$\{\text{Source IP}, \text{Source Port}, \text{Destination IP}, \text{Destination Port}\}$$
  *(along with the Layer 4 protocol identifier: TCP).*
- **Interview Insight**: This explains how a web server bound to a single local IP and port (e.g., `0.0.0.0:443`) can manage millions of simultaneous client connections—every active connection is demultiplexed by the operating system kernel via its unique combination of remote client IP and ephemeral client port.

---

### 17. Why is UDP preferred for video conferencing, online gaming, and DNS?
- **Direct Answer**: In real-time systems, **low latency is significantly more critical than 100% packet reliability**.
- **Three Core Technical Reasons**:
  1. **No Head-of-Line Blocking**: In TCP, if segment 2 is lost, segments 3, 4, and 5 must wait in receiver buffers until segment 2 is retransmitted. In live audio or gaming, a 300ms freeze destroys the user experience.
  2. **Obsolete Data**: A video frame or player coordinate from 250ms ago is completely useless. Dropping a lost video packet is unnoticeable; halting the stream to retransmit it causes severe lag.
  3. **Zero Handshake Overhead**: DNS queries require single-packet turnarounds; UDP avoids the multi-RTT handshake penalty.

---

### 18. What is a port number, and what are some well-known ports?
- **Direct Answer**: A port number is a 16-bit unsigned integer ($0–65535$) used by Layer 4 transport protocols to route incoming segments to the specific application or process running on the host OS.
- **Port Ranges**:
  - Well-Known / System Ports: $0–1023$ (requires root privilege).
  - Registered Ports: $1024–49151$ (vendor services like MySQL, Redis).
  - Dynamic / Ephemeral Ports: $49152–65535$ (temporary outbound client ports).
- **Must-Know Ports**:
  - `22`: SSH / SFTP
  - `25`: SMTP (Email routing)
  - `53`: DNS (UDP/TCP)
  - `67, 68`: DHCP (67: Server, 68: Client)
  - `80`: HTTP
  - `443`: HTTPS (TLS)
  - `3306`: MySQL \| `5432`: PostgreSQL \| `6379`: Redis

---

### 19. What is the `TIME_WAIT` state and why does it matter?
- **Direct Answer**: `TIME_WAIT` is the terminal state entered by whichever endpoint initiates an active close of a TCP connection. The socket remains in `TIME_WAIT` for **$2 \times \text{MSL}$** (Maximum Segment Lifetime, typically 1–2 minutes) before fully releasing resources.
- **Why It Exists**:
  1. **Ensures Reliable Teardown**: If the client's final `ACK` is lost in transit, the server will retransmit its `FIN`. If the client closed instantly, it would respond with an `RST` (Connection Reset) error instead of resending the ACK.
  2. **Drains Wandering Duplicates**: Allows delayed packets from the dead connection to expire in transit so they don't corrupt a new socket reusing the same IP:port combination.
- **Production Hazard**: In high-throughput microservices establishing rapid, short-lived HTTP connections without connection pooling, thousands of sockets accumulate in `TIME_WAIT`, causing **ephemeral port exhaustion** (`EADDRNOTAVAIL`).

---

### 20. How does TCP guarantee reliable byte-stream delivery?
- **Direct Answer**: TCP transforms an unreliable network layer (IP) into a guaranteed in-order byte stream using four coordinated mechanisms:
  1. **Sequence Numbers**: Every byte is assigned a sequential index so the receiver can reorder packets and discard duplicates.
  2. **Acknowledgments (Cumulative ACKs)**: The receiver explicitly informs the sender which bytes have been safely delivered.
  3. **Retransmission Timers (RTO & Fast Retransmit)**: The sender dynamically computes a Retransmission Timeout based on RTT; if an ACK is missing or if 3 duplicate ACKs are received, the segment is resent.
  4. **Checksums**: Detects bit-level payload corruption, causing corrupted packets to be silently dropped so retransmission mechanisms kick in.

## 3. Application Layer, DNS & Web

### 21. Is HTTP stateful or stateless? How do web applications maintain user sessions?
- **Direct Answer**: HTTP is inherently **stateless**—every request executed between a client and server is completely independent, and the server retains no memory of previous interactions.
- **Session Management Mechanisms**:
  1. **Cookies + Server-Side Sessions**: The server authenticates user credentials, creates a session record in memory/Redis, and issues an opaque `session_id` in a `Set-Cookie` header. The browser automatically includes this cookie in subsequent requests.
  2. **JWT (JSON Web Tokens - Stateless Tokens)**: The server signs a cryptographically secure token containing user claims (`userId`, `roles`) and returns it. The client stores it in memory or secure storage and transmits it in the `Authorization: Bearer <token>` header.
- **Security Attributes**: Session cookies must always specify `HttpOnly` (blocks XSS theft), `Secure` (HTTPS only), and `SameSite=Strict/Lax` (mitigates CSRF).

---

### 22. What are the key differences between HTTP/1.1, HTTP/2, and HTTP/3?
- **Direct Answer**:
  - **HTTP/1.1**: Plaintext ASCII protocol. Introduced persistent TCP connections (`Keep-Alive`), but suffers from **Head-of-Line (HoL) Blocking** at the application layer—only one request/response can travel over a TCP connection at a time.
  - **HTTP/2**: Binary framing. Introduced **Multiplexing** (multiple concurrent bidirectional request/response streams over a single TCP connection) and **HPACK** header compression. *Limitation*: Suffers from transport-layer HoL blocking (if one TCP packet drops, all streams stall).
  - **HTTP/3**: Completely replaces TCP with **QUIC over UDP**. Eliminates transport-layer HoL blocking entirely (packet loss in stream A has zero impact on stream B), supports 0-RTT connection resumption, and provides native connection migration when switching between Wi-Fi and mobile networks.

---

### 23. What does HTTPS actually protect against?
- **Direct Answer**: HTTPS executes HTTP inside an encrypted TLS/SSL tunnel on TCP port 443, providing the three core pillars of information security:
  1. **Confidentiality (Encryption)**: Encrypts the entire payload, headers, query parameters, cookies, and URLs. Eavesdroppers (ISPs, public Wi-Fi sniffers) see only random ciphertext.
  2. **Integrity**: Uses cryptographic Message Authentication Codes (MAC) to guarantee that packets cannot be modified, injected, or truncated in transit.
  3. **Authentication**: Uses X.509 digital certificates issued by trusted Certificate Authorities (CAs) to verify that the server is genuine, preventing Man-in-the-Middle (MitM) impersonation.

---

### 24. Briefly explain the SSL/TLS Handshake.
- **Direct Answer**: The TLS handshake authenticates the server's identity and derives a shared symmetric session key using asymmetric cryptography before application data begins flowing.
- **Key Steps (TLS 1.2 / 1.3)**:
  1. **ClientHello**: Client transmits supported TLS versions, cipher suites, and a random number ($R_c$).
  2. **ServerHello**: Server selects the cipher suite, sends random number ($R_s$), and presents its CA-signed digital SSL certificate.
  3. **Certificate Validation**: The browser verifies the certificate against its built-in trusted Root Certificate Authorities.
  4. **Key Exchange**: Using Diffie-Hellman (ECDHE), client and server exchange public parameters to independently compute an identical shared **symmetric session key**.
  5. **Finished**: Both sides verify handshake integrity and switch to ultra-fast **symmetric encryption** (e.g. AES-GCM) for all future data transmission.

---

### 25. Walk through DNS resolution when typing a URL and hitting Enter.
- **Direct Answer**: DNS resolves a human-readable domain name into a routable IP address through a hierarchical caching query pipeline:
  1. **Local Caches**: Browser Cache ➔ OS DNS Cache (`hosts` file) ➔ Local Router Cache.
  2. **Recursive Resolver**: If uncached, query is forwarded to the ISP or public recursive resolver (e.g., `8.8.8.8`).
  3. **Root Nameserver (`.`)**: Resolver queries a root server, which directs it to the Top-Level Domain (TLD) nameserver responsible for `.com`.
  4. **TLD Nameserver (`.com`)**: Points the resolver to the **Authoritative Nameserver** for `example.com`.
  5. **Authoritative Nameserver**: Contains the actual DNS zone file and returns the `A` record IPv4 address (e.g., `93.184.216.34`).
  6. **Caching**: The recursive resolver returns the IP to the OS and browser, caching it at each stage according to the record's **TTL (Time to Live)**.

---

### 26. What is the difference between an `A` record and a `CNAME` record?
- **Direct Answer**:
  - **`A` Record (Address)**: Maps a hostname directly to a physical **IPv4 address** (`example.com ➔ 93.184.216.34`). (`AAAA` maps to an IPv6 address).
  - **`CNAME` Record (Canonical Name)**: Maps an alias hostname to **another hostname** (`www.example.com ➔ example.com`). The DNS resolver must perform an additional lookup to resolve the canonical target's `A` record.
- **Crucial Rule**: Under RFC 1912, a `CNAME` record cannot coexist with other records at the zone apex/root domain (`@`).

---

### 27. What is a Load Balancer and what is the difference between L4 and L7?
- **Direct Answer**: A load balancer distributes incoming network traffic across multiple backend servers to maximize throughput, minimize latency, and eliminate single points of failure.
- **L4 vs. L7 Distinction**:
  - **L4 Load Balancing (Transport Layer)**: Makes routing decisions based purely on Layer 3/4 headers (Source/Destination IP and TCP/UDP port). It does not decrypt or inspect the HTTP payload. Extremely fast, protocol-agnostic, and CPU-efficient.
  - **L7 Load Balancing (Application Layer)**: Terminates TLS and inspects the HTTP request body, headers, cookies, and URL paths. Enables intelligent microservice routing (`/api/users` vs `/api/billing`), header rewrites, and cookie-based sticky sessions, at the cost of higher CPU overhead.

---

### 28. What does a CDN (Content Delivery Network) do?
- **Direct Answer**: A CDN is a geographically distributed network of edge proxy servers that caches static and dynamic web content (images, CSS, JS, video) physically close to end users.
- **Key Benefits**:
  1. **Cuts Latency**: Users fetch assets from a nearby edge node (<10ms) via Anycast routing instead of crossing international transit backbones to an origin server.
  2. **Reduces Origin Server Load**: Edge caches absorb 85–95% of incoming traffic.
  3. **DDoS Protection**: Massive distributed edge bandwidth absorbs large volumetric DDoS attacks before they reach backend infrastructure.

---

### 29. What is the difference between a Forward Proxy and a Reverse Proxy?
- **Direct Answer**:
  - **Forward Proxy (Client-Facing)**: Sits in front of **clients**. Hides client IP addresses from web servers, enforces enterprise web-filtering policies, bypasses geographic firewalls, and provides client anonymity.
  - **Reverse Proxy (Server-Facing)**: Sits in front of **backend servers**. Hides internal server IP addresses, provides centralized SSL/TLS termination, performs Layer 7 load balancing, and serves cached responses (e.g., Nginx, Envoy, Cloudflare).
- **Rule of Thumb**: A forward proxy protects and represents *clients*; a reverse proxy protects and represents *servers*.

---

### 30. Why does DNS sometimes use TCP instead of UDP?
- **Direct Answer**: DNS uses UDP port 53 by default for speed, low overhead, and single-packet query/response cycles. It switches to TCP port 53 in two specific scenarios:
  1. **Responses Exceeding 512 Bytes**: When a response is too large to fit in a standard UDP payload (common with DNSSEC cryptographic signatures or large TXT records), the server sets the **Truncation (`TC`) bit** in the UDP header, instructing the client to retry the query using TCP port 53.
  2. **Zone Transfers (AXFR/IXFR)**: Replicating entire DNS zone databases between primary and secondary nameservers requires TCP's guaranteed reliability and ordering.

## 4. Mixed, Practical & Security

### 31. What is a Firewall and how do stateful firewalls differ from stateless ones?
- **Direct Answer**: A firewall is a network security system that inspects and filters incoming and outgoing traffic based on configured security rules.
- **Stateless vs. Stateful**:
  - **Stateless Packet Filter (L3/L4)**: Inspects each packet in complete isolation based strictly on source/destination IP, port, and protocol. It has no memory of past packets and requires separate rules for inbound and outbound traffic.
  - **Stateful Firewall (L4)**: Maintains a state table tracking active TCP/UDP connections. When an outbound request is permitted, return traffic matching the established session is automatically allowed through without requiring a permissive inbound rule.
- **Next-Gen / WAF (Layer 7)**: Inspects application-layer payloads to block SQL injection, cross-site scripting (XSS), and malicious request structures.

---

### 32. What is a VPN and how does it work at a high level?
- **Direct Answer**: A Virtual Private Network creates a private, encrypted **tunnel** over an untrusted public network (the Internet) to securely connect a remote device to a private corporate network or secure proxy gateway.
- **Encapsulation & Tunneling Mechanism**:
  1. The client's VPN software takes the original IP packet (with destination and payload) and encrypts it entirely.
  2. It encapsulates this encrypted payload inside a brand new IP packet addressed to the remote VPN server using a tunneling protocol (e.g., WireGuard, IPsec, OpenVPN).
  3. The VPN server receives the packet, strips the outer header, decrypts the inner packet, and forwards it to the destination.
  4. The outside world sees only the VPN server's public IP address, masking the client's identity and encrypting data against local eavesdropping.

---

### 33. What is the difference between Symmetric and Asymmetric encryption?
- **Direct Answer**:
  - **Symmetric Encryption**: Uses a **single shared secret key** for both encryption and decryption. Extremely fast, hardware-accelerated, and ideal for bulk data transfer (e.g., AES-256, ChaCha20). *Challenge: Securely distributing the key across an untrusted network.*
  - **Asymmetric Encryption**: Uses a **mathematically linked key pair**—a Public Key (openly shared for encryption/verification) and a Private Key (kept secret for decryption/signing). Slower and CPU-intensive (e.g., RSA, ECC).
- **Hybrid Real-World Model**: Protocols like TLS combine both: asymmetric encryption authenticates identity and exchanges a shared session key during the handshake, then immediately switches to symmetric encryption for fast data transmission.

---

### 34. What is a DDoS attack and how is it mitigated?
- **Direct Answer**: A Distributed Denial of Service (DDoS) attack attempts to make an online service, network, or server unavailable by overwhelming it with a flood of malicious traffic generated from a distributed botnet.
- **Attack Classifications**:
  - **Layer 3/4 Volumetric & Protocol Attacks**: SYN Floods, UDP reflection, NTP amplification (aimed at exhausting bandwidth and connection backlogs).
  - **Layer 7 Application Attacks**: HTTP Floods, Slowloris (opening thousands of slow HTTP connections to exhaust web server worker threads).
- **Mitigation Strategies**: Anycast DNS routing (diluting traffic globally), CDN edge caching (absorbing reads), Web Application Firewalls (WAF), rate-limiting per IP/token, and enabling SYN Cookies.

---

### 35. What is packet loss and what typically causes it?
- **Direct Answer**: Packet loss occurs when one or more data packets traversing a computer network fail to reach their destination.
- **Primary Causes**:
  1. **Network Congestion (Most Common)**: High traffic fills up router and switch buffer queues, forcing devices to drop excess packets (**Tail Drop**).
  2. **Faulty Hardware & Media**: Damaged Ethernet cables, optical signal degradation, or radio frequency interference (Wi-Fi) causing checksum failures.
  3. **Routing Loops (TTL Expiry)**: Packets looping endlessly decrement TTL to 0 and are discarded with an ICMP Time Exceeded message.
- **Protocol Reactions**: TCP detects loss via duplicate ACKs or timeouts and retransmits while cutting $cwnd$; UDP drops packets permanently without retransmission.

---

### 36. Explain Latency vs. Bandwidth vs. Throughput.
- **Direct Answer**:
  - **Latency (Delay)**: The time it takes for a single data packet to travel from source to destination, measured in milliseconds (ms) or Round-Trip Time (RTT).
  - **Bandwidth (Capacity)**: The maximum theoretical data transfer rate of a network medium under ideal conditions (e.g., a 10 Gbps fiber link).
  - **Throughput (Actual Yield)**: The actual amount of data successfully transmitted and processed per unit time (always $\le$ bandwidth due to protocol overhead, packet loss, TCP window sizing, and latency).
- **Analogy**: Bandwidth is the diameter of a water pipe; Latency is how fast the water flows through it; Throughput is the actual volume of water exiting the tap per minute.

---

### 37. What is a MAC Address Flooding attack and how do switches mitigate it?
- **Direct Answer**:
  - **The Attack**: An attacker connects to a switch and floods it with thousands of bogus Ethernet frames with fake source MAC addresses. This exhausts the switch's finite **CAM (Content Addressable Memory) table**.
  - **The Consequence**: Once the CAM table is full, the switch cannot learn new valid MAC addresses and enters a fail-open state, behaving like a **Hub** by broadcasting all subsequent unicast traffic to every port, allowing the attacker to sniff traffic.
  - **The Defense**: Managed switches implement **Port Security**—restricting the maximum number of unique MAC addresses learned on a physical port and shutting down the interface or dropping frames if the threshold is violated.

### 38. Why is HTTPS recommended even for static websites without sensitive user data?
- **Direct Answer**:
  1. **Prevents ISP & Hotspot Injections**: ISPs and public Wi-Fi gateways cannot tamper with content, inject banner ads, or insert malicious tracking scripts into plain HTTP pages.
  2. **Data Integrity**: Guarantees that users receive the authentic, untampered static content published by the author.
  3. **Browser Security & SEO**: Modern browsers display alarming "Not Secure" warnings for plain HTTP; search engines prioritize HTTPS sites in rankings; and modern web APIs (Service Workers, HTTP/2 multiplexing) strictly require HTTPS.

### 39. What is a Socket? Walk through the basic socket programming API.
- **Direct Answer**: A socket is an operating system abstraction representing an active endpoint for bidirectional network communication across a network. It is identified by the 5-tuple: `(Protocol, Source IP, Source Port, Destination IP, Destination Port)`.
- **Standard Socket API Lifecycle (TCP)**:
  - **Server-Side**:
    1. `socket()`: Allocates an OS socket file descriptor.
    2. `bind()`: Associates the socket with a specific local IP and port.
    3. `listen()`: Sets the socket to passive mode and defines the connection backlog queue size.
    4. `accept()`: Blocks until a client connects, returning a brand-new connected socket dedicated to that client.
    5. `read()` / `write()`: Exchanging data.
    6. `close()`: Terminating the session.
  - **Client-Side**:
    1. `socket()` ➔ 2. `connect()` (triggers TCP 3-way handshake) ➔ 3. `write()` / `read()` ➔ 4. `close()`.

### 40. What is the difference between a Layer 2 and a Layer 3 device in simple terms?
- **Direct Answer**:
  - **Layer 2 Devices (Switches)**: Operate inside the **same local network / broadcast domain** using physical **MAC addresses**. They have no understanding of IP addresses or routing protocols. Their sole job is forwarding frames between adjacent physical ports on a LAN.
  - **Layer 3 Devices (Routers)**: Operate **across different, distinct networks** using logical **IP addresses**. They examine routing tables, evaluate routing protocols (BGP, OSPF), decrement TTL, break broadcast domains, and interconnect LANs to WANs and the public Internet.
