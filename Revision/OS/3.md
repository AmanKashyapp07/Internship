# CPU Scheduling — 10-Min Revision

Scope: scheduling criteria, FCFS, SJF, SRTF, Round Robin, Priority, starvation/aging, preemptive vs non-preemptive, MLFQ, real kernel schedulers.

---

## Core Theory

### 1. What is CPU Scheduling
Selecting which ready process/thread gets the CPU next and for how long. Needed whenever active processes outnumber CPU cores — kernel multiplexes CPU time for throughput + responsiveness.

### 2. Scheduling Criteria (5 metrics)
- **CPU Utilization** — % time CPU does useful work → maximize
- **Throughput** — processes completed per unit time → maximize
- **Turnaround Time** — completion − arrival → minimize
- **Waiting Time** — turnaround − burst (time in Ready Queue) → minimize
- **Response Time** — submission → first CPU response → minimize

### 3. FCFS (First-Come First-Served)
FIFO execution order.
- **Pros:** simple, no starvation
- **Convoy Effect:** one long CPU-bound process at front blocks many short I/O-bound processes behind it → degrades utilization

### 4. SJF (Shortest Job First)
Schedules shortest next burst first.
- **Why optimal:** mathematically minimizes average waiting time for a fixed process set
- **The catch:** not implementable in practice — future burst length is unknown, must be predicted (e.g., exponential moving average)

Example: A(10ms), B(2ms), C(2ms) — FCFS avg wait = 7.33ms vs SJF (B,C,A) avg wait = 2.00ms.

### 5. SRTF vs SJF
SRTF = **preemptive** version of SJF.
- **SJF:** non-preemptive, once running, keeps CPU until its burst finishes
- **SRTF:** preempts current process the moment a new arrival has a shorter *remaining* time

### 6. Round Robin
Fixed time quantum (~10–100ms), preempt on expiry, cycle through Ready Queue.
- **q too large** → degenerates to FCFS (bad response time)
- **q too small** → context-switch overhead dominates, throughput drops
- **Rule of thumb:** ~80% of CPU bursts should finish within one quantum

### 7. Priority Scheduling
Executes highest-priority ready process first; can be preemptive or non-preemptive.
- **Internal priority** — computed by OS (I/O:CPU burst ratio, memory needs)
- **External priority** — set by user/admin (e.g. `nice` in Linux)

### 8. Starvation
Indefinite postponement of a process because others keep jumping the queue.
- SJF/SRTF → long jobs starved by stream of short jobs
- Priority scheduling → low-priority tasks starved by high-priority tasks

### 9. Aging
Fix for starvation: gradually increase priority of processes waiting a long time, until they eventually get scheduled.

### 10. Preemptive vs Non-preemptive

| Dimension | Preemptive | Non-preemptive |
|---|---|---|
| Control | Kernel can interrupt anytime | Process yields voluntarily (finishes/blocks) |
| Responsiveness | High (good for GUI/real-time) | Low (long process can freeze others) |
| Overhead | High (frequent switches) | Low |
| Data safety | Needs locks for shared data | Naturally safe within a burst |

### 11. Algorithm Comparison

| Algorithm | Preemptive? | Starvation? | Pro | Con |
|---|---|---|---|---|
| FCFS | No | No | Simple | Convoy effect |
| SJF | No | Yes | Min avg wait | Needs future burst knowledge |
| SRTF | Yes | Yes | Optimal for short jobs | High preemption overhead |
| Round Robin | Yes | No | Great response time | Perf depends on quantum size |
| Priority | Both | Yes | Flexible control | Starvation without aging |
| MLFQ | Yes | Low | Adaptive | Complex to configure |

### 12. Real-World Schedulers (MLFQ family)
MLFQ = multiple queues with different quantum sizes; high-priority interactive queue (small quantum) → falls to lower-priority queues (larger quantum, more FCFS-like) as processes use up time slices.

- **Linux — EEVDF** (Earliest Eligible Virtual Deadline First, replaced CFS): uses red-black trees, tracks "virtual runtime" + deadlines for fairness + low latency
- **Windows NT/11:** 32-level priority-based preemptive MLFQ; dynamic priority boost when tasks wake from I/O
- **macOS/iOS (XNU):** Mach-based scheduler using QoS classes (User Interactive, User Initiated, Utility, Background)

## Interview Traps

1. **Recommending SJF for real OS design (wrong)** — SJF is a theoretical/idealized benchmark; real burst lengths aren't knowable in advance, only predictable via estimation.
2. **Turnaround time = waiting time (wrong)** — Turnaround = completion − arrival (includes execution + waiting). Waiting time = only the queue-idle portion.
3. **Preemption is pure software (wrong)** — relies on **hardware timer interrupts** firing periodically to hand control back to the scheduler.
4. **MLFQ ≠ priority scheduling (wrong)** — MLFQ **is** a dynamic priority scheme; it shifts tasks between priority queues based on observed behavior.
5. **Smaller Round Robin quantum is always better (wrong)** — too small a quantum means more CPU time spent context-switching than doing actual work, hurting throughput.

## Rapid-Fire Q&A

**Q: What is CPU scheduling?**
A: Deciding which ready process/thread runs next on the CPU and for how long.

**Q: Five scheduling criteria?**
A: CPU utilization, throughput, turnaround time, waiting time, response time.

**Q: What's the convoy effect?**
A: In FCFS, a long process blocks short processes queued behind it, hurting overall utilization.

**Q: Why is SJF optimal but impractical?**
A: It minimizes average waiting time mathematically, but requires knowing future burst length, which isn't possible — only predictable.

**Q: SRTF vs SJF?**
A: SRTF is the preemptive version — it interrupts the running process if a shorter-remaining-time process arrives; SJF runs to completion once started.

**Q: How do you pick a Round Robin time quantum?**
A: Large enough that ~80% of bursts finish within it — too large behaves like FCFS, too small wastes CPU on context switches.

**Q: Internal vs external priority?**
A: Internal = OS-computed (I/O:CPU ratio, memory need). External = user/admin-set (e.g., `nice`).

**Q: What causes starvation and what fixes it?**
A: Caused by short/high-priority tasks continuously jumping ahead; fixed by aging (gradually raising the waiting process's priority).

**Q: Preemptive vs non-preemptive?**
A: Preemptive — kernel can interrupt a running process anytime (better responsiveness, higher overhead). Non-preemptive — process only gives up CPU voluntarily.

**Q: What scheduler does Linux actually use?**
A: EEVDF (replaced CFS) — uses red-black trees, tracks virtual runtime/deadlines for fairness and low latency.

**Q: What do Windows and macOS use?**
A: Windows: 32-level priority-based preemptive MLFQ with I/O wake priority boosts. macOS/iOS: Mach-based scheduler with QoS classes.
