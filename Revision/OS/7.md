# Page Replacement — 10-Min Revision

Scope: why page replacement is needed, FIFO, LRU, OPT/Belady's, Clock/second-chance, Belady's Anomaly, thrashing, working set, why real LRU isn't implemented.

---

## Core Theory

### 1. Why Page Replacement is Needed
On a page fault with RAM full, OS must evict an existing in-memory page (writing it to swap if dirty) to free a frame for the new page. Without this, virtual memory couldn't exceed physical RAM.

### 2. FIFO
Evicts the oldest-loaded page, regardless of usage frequency/recency.
- Simple queue implementation
- **Drawback:** can evict heavily-used pages just because they loaded early (poor hit rate)

### 3. LRU (Least Recently Used)
Evicts the page unused for the longest time — relies on **temporal locality**.
- Great hit rates in practice
- **Challenge:** expensive to implement exactly — needs per-access timestamp/order tracking

### 4. Optimal (OPT / Belady's Algorithm)
Evicts the page that won't be used for the longest time **in the future**.
- Theoretical gold standard — lowest possible fault rate for a given reference string
- **Impossible in practice** — requires knowing the future access sequence; used only as an offline benchmark

### 5. Clock Algorithm (Second-Chance)
Practical LRU approximation using a circular queue + moving "clock hand."
- Each PTE has a hardware **Reference Bit**, set to 1 on access
- On eviction need: if Ref Bit == 1 → clear to 0, give second chance, advance hand. If Ref Bit == 0 → evict it now.

### 6. Belady's Anomaly
Counter-intuitive: **more RAM frames → more page faults**, for certain reference patterns.
- Happens in non-stack algorithms like **FIFO**
- **Never happens** in stack algorithms (LRU, OPT) — an N-frame page set is always a subset of the (N+1)-frame set

### 7. Thrashing
System spends more time paging (swap I/O) than executing actual instructions.
- **Root cause:** total working-set memory demand across processes exceeds physical RAM
- Vicious cycle: CPU utilization drops (waiting on disk I/O) → scheduler adds *more* processes → memory pressure worsens → more thrashing

### 8. Working Set
$W(t, \Delta)$ = set of distinct pages a process referenced in the most recent time window $\Delta$.
- **Working Set Model:** OS only schedules/runs a process if its full working set fits in RAM
- If total demand across processes exceeds RAM, OS suspends/swaps out an entire process to relieve pressure

### 9. Why real OSes don't implement true LRU
1. Massive overhead — updating exact order/timestamps on every memory access
2. Hardware limitation — x86/ARM MMUs provide only a single Reference/Accessed bit, not timestamps
3. Approximations (Clock, Linux Active/Inactive lists, Linux MGLRU) get ~95% of LRU's benefit at a fraction of the cost

## Interview Traps

1. **"Belady's Anomaly can happen under LRU" (wrong)** — never occurs under LRU/OPT (stack algorithms); it's specific to non-stack algorithms like FIFO.
2. **"High RAM usage = thrashing" (wrong)** — thrashing specifically means CPU progress collapses toward 0% due to continuous page-fault handling, not just high memory usage.
3. **"OPT can be implemented with smart buffering" (wrong)** — OPT needs exact future knowledge of memory references, impossible with real (non-deterministic) execution; it's a benchmark only.
4. **"Clock algorithm = FIFO" (wrong)** — Clock uses hardware reference bits to give pages a second chance, making it an LRU approximation, not a blind FIFO queue.

## Rapid-Fire Q&A

**Q: Why is page replacement needed?**
A: RAM is full at a page fault, so the OS must evict an existing page to free a frame for the new one.

**Q: How does FIFO work and what's its flaw?**
A: Evicts the oldest-loaded page; can evict frequently-used pages just because they were loaded early.

**Q: How does LRU work?**
A: Evicts the page unused for longest, based on temporal locality; great hit rate but expensive to track exactly.

**Q: What is Optimal page replacement and why isn't it used?**
A: Evicts the page not needed for longest in the future; theoretically best fault rate, but requires future knowledge — used only as a benchmark.

**Q: How does the Clock/Second-Chance algorithm work?**
A: Circular queue with a reference bit per page; if bit=1, clear it and give a second chance (advance hand); if bit=0, evict.

**Q: What is Belady's Anomaly and where does it occur?**
A: More frames causing more faults; occurs in FIFO (non-stack algorithm), never in LRU/OPT (stack algorithms).

**Q: What is thrashing and what causes it?**
A: System spends more time paging than executing; caused by combined working-set demand exceeding physical RAM, worsened by scheduler adding more processes.

**Q: What is the working set model?**
A: Tracks each process's recently referenced pages ($W(t,\Delta)$); only schedules a process if its working set fits in RAM, else suspends a process to relieve pressure.

**Q: Why don't real OSes use true LRU?**
A: Too much overhead to track exact access order; hardware only gives a reference bit, not timestamps — so approximations (Clock, MGLRU) are used instead.
