# L3 — CPU Scheduling

> **Internship Focus**: Expect both conceptual questions (which algorithm is preemptive, which suffers from starvation?) and **numerical problems** (calculate Turnaround Time and Waiting Time from a Gantt chart). These are common at Amazon, Flipkart, and service-based companies.

---

## 1. Why CPU Scheduling?

In a multiprogramming/multitasking OS, multiple processes compete for the CPU at all times. The **CPU scheduler** (Short-Term Scheduler) picks which process in the Ready Queue gets the CPU next.

**Goals of CPU scheduling**:
- Maximize **CPU utilization** (keep the CPU busy)
- Maximize **throughput** (processes completed per unit time)
- Minimize **Turnaround Time** (time from submission to completion)
- Minimize **Waiting Time** (total time spent in Ready Queue)
- Minimize **Response Time** (time until first response — critical for interactive systems)
- **Fairness** (no process should wait forever — starvation)

---

## 2. Key Metrics (Must Know Numerically)

| Metric | Formula | Meaning |
|--------|---------|---------|
| **Arrival Time (AT)** | Given | When the process enters the Ready Queue |
| **Burst Time (BT)** | Given | CPU time needed to complete |
| **Completion Time (CT)** | From Gantt chart | When process finishes |
| **Turnaround Time (TAT)** | CT - AT | Total time from arrival to completion |
| **Waiting Time (WT)** | TAT - BT | Time spent waiting in Ready Queue |
| **Response Time (RT)** | First CPU start - AT | Time until process first gets the CPU |

---

## 3. Preemptive vs. Non-Preemptive

| | **Non-Preemptive** | **Preemptive** |
|-|-------------------|----------------|
| **Description** | Once a process starts executing, it runs until it finishes or does I/O (voluntarily gives up CPU) | OS can forcibly take CPU away from a running process |
| **Good for** | Batch systems, simple implementation | Interactive/real-time systems |
| **Problem** | One process can hog CPU (convoy effect) | Race conditions possible (need synchronization) |

---

## 4. Scheduling Algorithms

### 4.1 First Come First Serve (FCFS)
- **Type**: Non-preemptive
- **Rule**: Processes are served in the order they arrive (FIFO queue).

**Example**:
| Process | AT | BT |
|---------|----|----|
| P1 | 0 | 10 |
| P2 | 1 | 4 |
| P3 | 2 | 3 |

**Gantt Chart**: `| P1 (0-10) | P2 (10-14) | P3 (14-17) |`

| Process | CT | TAT | WT |
|---------|----|----|-----|
| P1 | 10 | 10 | 0 |
| P2 | 14 | 13 | 9 |
| P3 | 17 | 15 | 12 |
| **Avg** | | **12.67** | **7** |

**⚠️ Convoy Effect**: A long process monopolizes the CPU, causing short processes to wait a very long time. Like a slow truck blocking a highway.

---

### 4.2 Shortest Job First (SJF) — Non-Preemptive
- **Type**: Non-preemptive
- **Rule**: Among available processes, pick the one with the **shortest burst time**. Ties broken by arrival order.
- **Optimal** for minimizing average waiting time among non-preemptive algorithms.

**Example** (same processes):
At time 0, only P1 is available → run P1.
At time 10, P2 (BT=4) and P3 (BT=3) are both available → run P3 first.

**Gantt Chart**: `| P1 (0-10) | P3 (10-13) | P2 (13-17) |`

| Process | CT | TAT | WT |
|---------|----|----|-----|
| P1 | 10 | 10 | 0 |
| P2 | 17 | 16 | 12 |
| P3 | 13 | 11 | 8 |
| **Avg** | | **12.33** | **6.67** |

**Problems with SJF**:
- **Starvation** (if short jobs keep arriving, long jobs never execute).
- **Burst time prediction** is hard — OS can't know in advance how long a process will run. Uses historical average (exponential averaging).

---

### 4.3 Shortest Remaining Time First (SRTF) — Preemptive SJF
- **Type**: Preemptive version of SJF
- **Rule**: At every new arrival, compare its burst time with the **remaining burst time** of the current running process. Preempt if the new process is shorter.
- **Optimal** for minimizing average waiting time overall (among all preemptive algorithms).

**Example**:
| Process | AT | BT |
|---------|----|----|
| P1 | 0 | 8 |
| P2 | 1 | 4 |
| P3 | 2 | 2 |

- t=0: P1 starts (only option, remaining=8)
- t=1: P2 arrives (BT=4 < P1 remaining=7) → preempt P1, run P2
- t=2: P3 arrives (BT=2 < P2 remaining=3) → preempt P2, run P3
- t=4: P3 done, P2 remaining=3, P1 remaining=7 → run P2
- t=7: P2 done, P1 remaining=7 → run P1
- t=14: P1 done

**Gantt Chart**: `| P1(0-1) | P2(1-2) | P3(2-4) | P2(4-7) | P1(7-14) |`

---

### 4.4 Priority Scheduling
- **Type**: Can be Preemptive or Non-Preemptive
- **Rule**: Each process has a priority number. CPU goes to highest priority process. (Convention: lower number = higher priority, or higher number = higher priority — check the problem!)

**⚠️ Starvation**: Low-priority processes may never get CPU if high-priority processes keep arriving.
**✅ Solution — Aging**: Gradually increase the priority of a waiting process over time. A process that has waited long enough will eventually get a high enough priority to execute.

---

### 4.5 Round Robin (RR)
- **Type**: Preemptive
- **Rule**: Each process gets a fixed **time quantum (Q)** to execute. If not finished in Q units, it's preempted and put at the end of the Ready Queue.
- **Best for**: Time-sharing / interactive systems (low response time).

**Choosing Time Quantum**:
- **Q too large** → degenerates into FCFS.
- **Q too small** → too many context switches (overhead dominates).
- **Rule of thumb**: Q should be slightly larger than the typical CPU burst.

**Example** (Q = 3):
| Process | AT | BT |
|---------|----|----|
| P1 | 0 | 5 |
| P2 | 0 | 3 |
| P3 | 0 | 7 |

**Gantt Chart**: `| P1(0-3) | P2(3-6) | P3(6-9) | P1(9-11) | P3(11-14) | P3(14-15)... wait, P3 remaining=4 after t=9, then P1 takes 2, so P3 gets 4 more |`

Corrected: `| P1(0-3) | P2(3-6) | P3(6-9) | P1(9-11) | P3(11-15) |`

| Process | CT | TAT | WT |
|---------|----|----|-----|
| P1 | 11 | 11 | 6 |
| P2 | 6 | 6 | 3 |
| P3 | 15 | 15 | 8 |
| **Avg** | | **10.67** | **5.67** |

---

### 4.6 Multi-Level Queue (MLQ)
- Ready queue is divided into **separate queues** based on process type (e.g., foreground/interactive vs. background/batch).
- Each queue has its own scheduling algorithm (e.g., RR for foreground, FCFS for background).
- **Fixed priority between queues**: Foreground queue is always served before background → **starvation possible** for background.

```
[ Foreground (Interactive) ] — Round Robin (RR)
[ Background (Batch)       ] — FCFS
[ System Processes         ] — Highest priority, always first
```

### 4.7 Multi-Level Feedback Queue (MLFQ)
- Like MLQ, but processes can **move between queues** based on behavior.
- **Idea**: Start all processes in highest-priority queue (short quantum). If they use their full quantum → demote to lower queue (they're CPU-intensive). Processes that do I/O quickly stay in high-priority queues.
- **Aging built in**: Processes that wait too long get promoted.
- **Most versatile, most complex** — used in modern OS (Linux's CFS is conceptually similar, Windows uses a feedback-based scheme).

## 5. Scheduling Algorithm Comparison Table

| Algorithm | Type | Starvation? | Convoy Effect? | Optimal For | Best Avg WT? |
|-----------|------|-------------|----------------|-------------|--------------|
| FCFS | Non-preemptive | No | Yes | Simple batch | No |
| SJF | Non-preemptive | Yes | No | Min avg WT (non-preemptive) | Among non-preemptive |
| SRTF | Preemptive | Yes | No | Min avg WT overall | **Yes (globally optimal)** |
| Priority | Both | Yes | No | Priority-based systems | No |
| Round Robin | Preemptive | No | No | Interactive, time-sharing | No (but best response time) |
| MLQ | Both | Yes (lower queues) | No | Structured environments | No |
| MLFQ | Preemptive | No (with aging) | No | General-purpose OS | Close to optimal |

## 6. Gantt Chart Tips for Numeric Problems

**Steps to solve a scheduling problem**:
1. List processes with AT and BT.
2. Simulate step-by-step: at each decision point, apply the algorithm's rule to pick the next process.
3. Draw the Gantt chart.
4. Compute CT from Gantt chart (when each process last finishes).
5. TAT = CT - AT for each process.
6. WT = TAT - BT for each process.
7. Average TAT = Sum of all TAT / number of processes.
8. Average WT = Sum of all WT / number of processes.
