## 1. SQL Overview

**SQL (Structured Query Language)** is the standard language for interacting with relational databases.

### SQL Sub-languages:

| Sub-language | Full Form | Commands |
|---|---|---|
| **DDL** | Data Definition Language | CREATE, ALTER, DROP, TRUNCATE, RENAME |
| **DML** | Data Manipulation Language | SELECT, INSERT, UPDATE, DELETE |
| **DCL** | Data Control Language | GRANT, REVOKE |
| **TCL** | Transaction Control Language | COMMIT, ROLLBACK, SAVEPOINT |

---

## 2. DDL — Data Definition Language

### CREATE TABLE
```sql
CREATE TABLE Student (
    StudentID   INT          PRIMARY KEY,
    Name        VARCHAR(50)  NOT NULL,
    Email       VARCHAR(100) UNIQUE,
    Age         INT          CHECK (Age >= 0),
    DeptID      INT          REFERENCES Department(DeptID) ON DELETE SET NULL,
    JoinDate    DATE         DEFAULT CURRENT_DATE
);
```

### Constraints in CREATE:
| Constraint | Purpose |
|---|---|
| `PRIMARY KEY` | Unique + NOT NULL identifier |
| `NOT NULL` | Attribute cannot be NULL |
| `UNIQUE` | All values must be distinct (NULLs allowed, treated as distinct) |
| `CHECK(condition)` | Domain constraint |
| `DEFAULT value` | Used when no value is provided |
| `REFERENCES` | Foreign key reference |

### ALTER TABLE
```sql
ALTER TABLE Student ADD COLUMN Phone VARCHAR(15);         -- add column
ALTER TABLE Student DROP COLUMN Phone;                    -- remove column
ALTER TABLE Student MODIFY COLUMN Age SMALLINT;           -- change type (MySQL)
ALTER TABLE Student ALTER COLUMN Age TYPE SMALLINT;       -- PostgreSQL syntax
ALTER TABLE Student ADD CONSTRAINT chk_age CHECK(Age>=0); -- add constraint
ALTER TABLE Student DROP CONSTRAINT chk_age;              -- drop constraint
ALTER TABLE Student RENAME COLUMN Name TO FullName;       -- rename column
```

### DROP vs TRUNCATE vs DELETE

| | DROP | TRUNCATE | DELETE |
|---|---|---|---|
| **What it removes** | Table + data + structure | All rows (keeps structure) | Specific / all rows |
| **DDL or DML** | DDL | DDL | DML |
| **Rollback possible** | No (in most RDBMS) | No (in most RDBMS) | Yes |
| **WHERE clause** | No | No | Yes |
| **Triggers fired** | No | No | Yes |
| **Resets auto-increment** | Yes | Yes | No |
| **Speed** | Fastest | Fast | Slower (row-by-row) |

## 3. DML — Data Manipulation Language

### INSERT
```sql
-- single row
INSERT INTO Student (StudentID, Name, Email, Age, DeptID)
VALUES (101, 'Ravi', 'ravi@mail.com', 20, 10);

-- multiple rows
INSERT INTO Student VALUES
    (102, 'Priya', 'priya@mail.com', 21, 20),
    (103, 'Amit', 'amit@mail.com', 22, 10);

-- insert from another table
INSERT INTO Archive_Student SELECT * FROM Student WHERE Age > 25;
```

### UPDATE
```sql
UPDATE Student
SET Age = 21, DeptID = 20
WHERE StudentID = 101;
```

### DELETE
```sql
DELETE FROM Student WHERE Age > 25;   -- delete specific rows
DELETE FROM Student;                   -- delete all rows (DML, rollback possible)
```

## 4. SELECT — The Core Query

### Clause Execution Order (Critical for interviews)
```
FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT
```
> SQL is **written** in a different order than it is **executed**. Memorise the execution order — it explains why you can't use aliases from SELECT in WHERE.

### Basic SELECT
```sql
SELECT Name, Age
FROM Student
WHERE Age > 18
ORDER BY Age DESC
LIMIT 5;
```

### DISTINCT
```sql
SELECT DISTINCT DeptID FROM Student;   -- removes duplicate rows in result
```

### Aliases
```sql
SELECT Name AS StudentName, Age * 12 AS AgeInMonths FROM Student;
SELECT s.Name, d.DeptName FROM Student s, Department d;   -- table alias
```

## 5. WHERE Clause & Operators

```sql
WHERE Age BETWEEN 18 AND 25          -- inclusive on both ends
WHERE Name LIKE 'R%'                 -- starts with R
WHERE Name LIKE '_avi'               -- second char onward is 'avi'
WHERE DeptID IN (10, 20, 30)         -- membership
WHERE DeptID NOT IN (10, 20)
WHERE Email IS NULL                  -- NULL check (never use = NULL)
WHERE Email IS NOT NULL
WHERE Age > 18 AND DeptID = 10
WHERE Age > 18 OR DeptID = 10
WHERE NOT Age > 18
```

### LIKE wildcards:
- `%` — zero or more characters
- `_` — exactly one character

## 6. Aggregate Functions

```sql
SELECT COUNT(*)          FROM Student;           -- count all rows incl. NULLs
SELECT COUNT(Email)      FROM Student;           -- count non-NULL emails only
SELECT COUNT(DISTINCT DeptID) FROM Student;      -- distinct count
SELECT SUM(Age)          FROM Student;
SELECT AVG(Age)          FROM Student;           -- ignores NULLs
SELECT MAX(Age)          FROM Student;
SELECT MIN(Age)          FROM Student;
```

> All aggregate functions **ignore NULL values** except `COUNT(*)`.

---

## 7. GROUP BY & HAVING

```sql
SELECT DeptID, COUNT(*) AS StudentCount, AVG(Age) AS AvgAge
FROM Student
GROUP BY DeptID
HAVING COUNT(*) > 5;
```

### Key rules:
- Every column in SELECT must either be in `GROUP BY` or wrapped in an aggregate function
- `WHERE` filters **before** grouping (on individual rows)
- `HAVING` filters **after** grouping (on groups)
- You **cannot** use aggregate functions in `WHERE`

```sql
-- WRONG: can't use aggregate in WHERE
SELECT DeptID FROM Student WHERE COUNT(*) > 5 GROUP BY DeptID;

-- CORRECT: use HAVING
SELECT DeptID FROM Student GROUP BY DeptID HAVING COUNT(*) > 5;
```

## 8. JOINs

### INNER JOIN
Returns rows where there is a **match in both tables**.
```sql
SELECT s.Name, d.DeptName
FROM Student s
INNER JOIN Department d ON s.DeptID = d.DeptID;
```

### LEFT OUTER JOIN
Returns **all rows from the left table** + matched rows from right. Unmatched right = NULL.
```sql
SELECT s.Name, d.DeptName
FROM Student s
LEFT JOIN Department d ON s.DeptID = d.DeptID;
```

### RIGHT OUTER JOIN
Returns **all rows from the right table** + matched rows from left. Unmatched left = NULL.
```sql
SELECT s.Name, d.DeptName
FROM Student s
RIGHT JOIN Department d ON s.DeptID = d.DeptID;
```

### FULL OUTER JOIN
Returns **all rows from both tables**. NULLs filled where no match.
```sql
SELECT s.Name, d.DeptName
FROM Student s
FULL OUTER JOIN Department d ON s.DeptID = d.DeptID;
```

### CROSS JOIN
Returns the **Cartesian product** — every row of A paired with every row of B.
```sql
SELECT * FROM Student CROSS JOIN Course;
-- if Student has 100 rows and Course has 10, result has 1000 rows
```

### SELF JOIN
A table joined **with itself**.
```sql
-- Find all employees and their managers
SELECT e.Name AS Employee, m.Name AS Manager
FROM Employee e
JOIN Employee m ON e.ManagerID = m.EmpID;
```

### JOIN summary:

| JOIN Type | Returns |
|---|---|
| INNER JOIN | Only matching rows from both |
| LEFT JOIN | All from left + matching from right |
| RIGHT JOIN | All from right + matching from left |
| FULL OUTER JOIN | All from both, NULLs where no match |
| CROSS JOIN | Every combination (Cartesian product) |
| SELF JOIN | Table joined with itself |

## 9. Subqueries

A query **nested inside** another query.

### In WHERE
```sql
-- students in the same dept as 'Ravi'
SELECT Name FROM Student
WHERE DeptID = (SELECT DeptID FROM Student WHERE Name = 'Ravi');
```

### In FROM (Derived Table / Inline View)
```sql
SELECT DeptID, AvgAge
FROM (SELECT DeptID, AVG(Age) AS AvgAge FROM Student GROUP BY DeptID) AS DeptAvg
WHERE AvgAge > 20;
```

### In SELECT (Scalar Subquery)
```sql
SELECT Name,
       (SELECT DeptName FROM Department d WHERE d.DeptID = s.DeptID) AS Dept
FROM Student s;
```

### Correlated Subquery
The inner query **references the outer query** — re-executed for each outer row.
```sql
-- students older than the average age of their own department
SELECT Name FROM Student s
WHERE Age > (SELECT AVG(Age) FROM Student WHERE DeptID = s.DeptID);
```

## 10. EXISTS vs IN

### IN
- Checks if a value is in a **list or subquery result set**
- Works well with small result sets
- Returns FALSE for NULL values in the list (tricky!)

```sql
SELECT Name FROM Student
WHERE DeptID IN (SELECT DeptID FROM Department WHERE DeptName = 'CS');
```

### EXISTS
- Checks if the subquery **returns at least one row** (TRUE/FALSE)
- Stops as soon as one match is found — more efficient for large sets
- Works well with correlated subqueries

```sql
SELECT Name FROM Student s
WHERE EXISTS (
    SELECT 1 FROM Enrollment e WHERE e.StudentID = s.StudentID
);
```

### Key difference:
| | IN | EXISTS |
|---|---|---|
| What it checks | Value in a set | At least one row exists |
| NULL handling | NULL in list → FALSE | NULL safe |
| Performance | Better for small sets | Better for large/correlated |
| Short-circuit | No | Yes |

## 11. UNION, INTERSECT, EXCEPT

```sql
-- All students OR employees (no duplicates)
SELECT Name FROM Student
UNION
SELECT Name FROM Employee;

-- All students AND employees (names in both)
SELECT Name FROM Student
INTERSECT
SELECT Name FROM Employee;

-- Students who are NOT employees
SELECT Name FROM Student
EXCEPT
SELECT Name FROM Employee;
```

### UNION vs UNION ALL:
- `UNION` — removes duplicates (slower)
- `UNION ALL` — keeps all rows including duplicates (faster)

### Rules:
- Both queries must have the **same number of columns**
- Corresponding columns must have **compatible data types**
- Column names come from the **first query**

## 12. NULL Handling in SQL Queries

```sql
-- WRONG way to check NULL
WHERE Email = NULL        -- always returns no rows (NULL ≠ NULL)

-- CORRECT
WHERE Email IS NULL
WHERE Email IS NOT NULL

-- COALESCE: returns first non-NULL value
SELECT COALESCE(Phone, Email, 'No Contact') FROM Student;

-- NULLIF: returns NULL if two values are equal, otherwise returns first
SELECT NULLIF(Score, 0) FROM Results;   -- returns NULL instead of 0

-- NULL in aggregate
SELECT AVG(Score) FROM Results;   -- ignores NULLs; not the same as treating them as 0
```

## 13. Useful Clauses

### ORDER BY
```sql
ORDER BY Age ASC, Name DESC    -- multiple sort keys
ORDER BY 2 DESC                -- sort by 2nd column in SELECT list
```

### LIMIT / OFFSET (pagination)
```sql
SELECT * FROM Student ORDER BY StudentID LIMIT 10 OFFSET 20;
-- skip first 20 rows, return next 10
```

### BETWEEN
```sql
WHERE Age BETWEEN 18 AND 25   -- equivalent to Age >= 18 AND Age <= 25
```

### CASE Expression
```sql
SELECT Name,
    CASE
        WHEN Age < 18 THEN 'Minor'
        WHEN Age BETWEEN 18 AND 25 THEN 'Young Adult'
        ELSE 'Adult'
    END AS AgeGroup
FROM Student;
```

## 14. Practice Queries (Classic Interview Problems)

**Schema:**
```
Student(StudentID, Name, Age, DeptID)
Department(DeptID, DeptName)
Course(CourseID, CourseName, Credits)
Enrollment(StudentID, CourseID, Grade)
```

**Q: Find the second highest age among students.**
```sql
SELECT MAX(Age) FROM Student
WHERE Age < (SELECT MAX(Age) FROM Student);
```

**Q: Find departments with more than 3 students.**
```sql
SELECT d.DeptName, COUNT(*) AS Total
FROM Student s JOIN Department d ON s.DeptID = d.DeptID
GROUP BY d.DeptID, d.DeptName
HAVING COUNT(*) > 3;
```

**Q: Find students who have not enrolled in any course.**
```sql
-- Using NOT IN
SELECT Name FROM Student
WHERE StudentID NOT IN (SELECT StudentID FROM Enrollment);

-- Using NOT EXISTS
SELECT Name FROM Student s
WHERE NOT EXISTS (SELECT 1 FROM Enrollment e WHERE e.StudentID = s.StudentID);

-- Using LEFT JOIN
SELECT s.Name FROM Student s
LEFT JOIN Enrollment e ON s.StudentID = e.StudentID
WHERE e.StudentID IS NULL;
```

**Q: Find the student with the highest average grade.**
```sql
SELECT StudentID, AVG(Grade) AS AvgGrade
FROM Enrollment
GROUP BY StudentID
ORDER BY AvgGrade DESC
LIMIT 1;
```

**Q: Find students enrolled in all courses.**
```sql
SELECT StudentID FROM Enrollment
GROUP BY StudentID
HAVING COUNT(DISTINCT CourseID) = (SELECT COUNT(*) FROM Course);
```

**Q: Find duplicate emails in Student table.**
```sql
SELECT Email, COUNT(*) FROM Student
GROUP BY Email
HAVING COUNT(*) > 1;
```

## 15. Interview Questions & Answers

**Q1. What is the difference between WHERE and HAVING?**
> WHERE filters individual rows **before** grouping and cannot use aggregate functions. HAVING filters groups **after** GROUP BY and can use aggregate functions. If there is no GROUP BY, HAVING acts like WHERE but this is unusual.

---

**Q2. What is the execution order of SQL clauses?**
> FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT. This is why you can't reference a SELECT alias in a WHERE clause — WHERE executes before SELECT assigns the alias.

---

**Q3. What is the difference between DELETE, TRUNCATE, and DROP?**
> DELETE is DML — removes specific rows, supports WHERE, fires triggers, and can be rolled back. TRUNCATE is DDL — removes all rows instantly, cannot be rolled back (in most RDBMS), and resets auto-increment. DROP removes the entire table including its structure and cannot be rolled back.

---

**Q4. What is a correlated subquery? How is it different from a normal subquery?**
> A normal (non-correlated) subquery executes once and its result is used by the outer query. A correlated subquery references columns from the outer query, so it is re-executed once for every row of the outer query — making it slower but capable of row-specific comparisons.

---

**Q5. What is the difference between UNION and UNION ALL?**
> UNION removes duplicate rows from the combined result (uses extra sorting/hashing). UNION ALL retains all rows including duplicates and is faster. Use UNION ALL unless you specifically need deduplication.

---

**Q6. Why does `NOT IN` behave unexpectedly with NULLs?**
> If the subquery in `NOT IN` returns even one NULL, the entire `NOT IN` returns no rows. This is because `x NOT IN (1, 2, NULL)` translates to `x ≠ 1 AND x ≠ 2 AND x ≠ NULL`. Since `x ≠ NULL` evaluates to UNKNOWN, the whole condition becomes UNKNOWN, not TRUE. Use `NOT EXISTS` to safely handle NULLs.

---

**Q7. What is a self join? When would you use it?**
> A self join joins a table with itself using table aliases. It is used when a table has a hierarchical or recursive relationship within itself. Example: an Employee table where `ManagerID` references `EmpID` in the same table — a self join finds each employee and their manager's name.

---

**Q8. What is the difference between INNER JOIN and LEFT JOIN?**
> INNER JOIN returns only rows where there is a match in both tables. LEFT JOIN returns all rows from the left table; for rows with no match in the right table, right-side columns are NULL. Use LEFT JOIN when you want to keep all records from the left table regardless of whether a match exists.

---

**Q9. Can you use GROUP BY without SELECT aggregates?**
> Yes — GROUP BY can be used without aggregate functions to get distinct combinations of the grouped columns. It is essentially a verbose way to get DISTINCT on multiple columns. However, in practice, GROUP BY without aggregates is rare and DISTINCT is cleaner.

---

**Q10. How do you find the Nth highest salary (or value)?**
```sql
-- Nth highest salary (N = 3)
SELECT DISTINCT Salary FROM Employee
ORDER BY Salary DESC
LIMIT 1 OFFSET N-1;      -- OFFSET 2 for 3rd highest

-- or using subquery
SELECT MIN(Salary) FROM (
    SELECT DISTINCT Salary FROM Employee
    ORDER BY Salary DESC
    LIMIT N
) AS TopN;
```

## 16. Common Traps & Edge Cases

| Trap | Clarification |
|---|---|
| `WHERE col = NULL` | Always false — use `IS NULL` |
| Alias in WHERE | Not allowed — WHERE runs before SELECT |
| `COUNT(col)` vs `COUNT(*)` | `COUNT(col)` skips NULLs; `COUNT(*)` counts all rows |
| `AVG` with NULLs | NULLs ignored — not treated as 0; result can be misleading |
| `NOT IN` with NULL in subquery | Returns empty result — use `NOT EXISTS` instead |
| `BETWEEN` inclusivity | Both endpoints are **inclusive** |
| `UNION` column count | Both queries must have same number of columns |
| `HAVING` without `GROUP BY` | Treats entire table as one group |
| `DISTINCT` on multiple columns | Applied to the **combination** of all selected columns |
| `TRUNCATE` vs `DELETE` rollback | TRUNCATE cannot be rolled back in MySQL/Oracle; DELETE can |

## 17. Quick Revision Snapshot

```
SQL sub-languages: DDL (CREATE/ALTER/DROP) | DML (SELECT/INSERT/UPDATE/DELETE)
                   DCL (GRANT/REVOKE) | TCL (COMMIT/ROLLBACK)

Execution order:   FROM → JOIN → WHERE → GROUP BY → HAVING
                   → SELECT → DISTINCT → ORDER BY → LIMIT

WHERE  → filters rows (before grouping); no aggregates allowed
HAVING → filters groups (after GROUP BY); aggregates allowed

JOINs:
  INNER  → match in both
  LEFT   → all left + matched right (NULLs for unmatched)
  RIGHT  → all right + matched left
  FULL   → all from both
  CROSS  → Cartesian product
  SELF   → table with itself (use aliases)

Subqueries:
  Non-correlated → runs once
  Correlated     → runs per outer row (slower)
  EXISTS vs IN   → EXISTS is NULL-safe and short-circuits

NULL rules:
  = NULL → always UNKNOWN; use IS NULL
  Aggregates ignore NULLs (except COUNT(*))
  NOT IN with NULL in list → no rows returned; use NOT EXISTS

DROP vs TRUNCATE vs DELETE:
  DROP     → removes table entirely; DDL; no rollback
  TRUNCATE → removes all rows; DDL; no rollback; resets auto-increment
  DELETE   → removes rows; DML; rollback possible; fires triggers
```
