# L11 — SQL Problem Patterns (High-Frequency Interview Queries)

> **Target**: Top IT company internship interviews — SQL rounds at Amazon, Microsoft, Flipkart, etc.

---

## Why This Matters

SQL writing is tested differently from SQL theory. Interviewers give you a table schema and ask you to write a query. This lecture covers the **most common patterns** with clean, reusable templates.

---

## Pattern 1: Ranking / Top-N per Group

### Find the 2nd highest salary

```sql
-- Method 1: DENSE_RANK (handles ties correctly)
SELECT salary
FROM (
    SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk
    FROM Employee
) ranked
WHERE rnk = 2;

-- Method 2: Subquery (simple but slower)
SELECT MAX(salary) FROM Employee
WHERE salary < (SELECT MAX(salary) FROM Employee);

-- Method 3: LIMIT/OFFSET (MySQL)
SELECT DISTINCT salary FROM Employee
ORDER BY salary DESC
LIMIT 1 OFFSET 1;
```

### Find the Nth highest salary (generalised)

```sql
-- Using window function (works for any N)
SELECT salary FROM (
    SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk
    FROM Employee
) t WHERE rnk = N;
```

### Top 1 earner per department

```sql
SELECT department, employee_name, salary
FROM (
    SELECT department, employee_name, salary,
           RANK() OVER (PARTITION BY department ORDER BY salary DESC) AS rnk
    FROM Employee
) ranked
WHERE rnk = 1;
```

> **Trap**: Use `RANK` or `DENSE_RANK`, not `ROW_NUMBER` when multiple employees can have the same salary.

## Pattern 2: Running Totals & Moving Averages

```sql
-- Running total of sales ordered by date
SELECT
    sale_date,
    amount,
    SUM(amount) OVER (ORDER BY sale_date) AS running_total
FROM Sales;

-- 3-day moving average
SELECT
    sale_date,
    amount,
    AVG(amount) OVER (
        ORDER BY sale_date
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ) AS moving_avg_3day
FROM Sales;

-- Cumulative sum per customer (partitioned)
SELECT
    customer_id,
    sale_date,
    amount,
    SUM(amount) OVER (PARTITION BY customer_id ORDER BY sale_date) AS cumulative_spent
FROM Sales;
```

## Pattern 3: Consecutive / Gap Problems

### Find users who logged in on 3 or more consecutive days

```sql
WITH numbered AS (
    SELECT user_id, login_date,
           ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date) AS rn
    FROM (SELECT DISTINCT user_id, login_date FROM Logins) t
),
groups AS (
    SELECT user_id, login_date,
           DATE_SUB(login_date, INTERVAL rn DAY) AS grp   -- same grp = consecutive
    FROM numbered
)
SELECT user_id
FROM groups
GROUP BY user_id, grp
HAVING COUNT(*) >= 3;
```

### Find customers with no orders in the last 30 days

```sql
SELECT c.customer_id, c.name
FROM Customer c
LEFT JOIN Orders o
    ON c.customer_id = o.customer_id
    AND o.order_date >= CURDATE() - INTERVAL 30 DAY
WHERE o.order_id IS NULL;
```

## Pattern 4: Self-Joins

### Find employees who earn more than their manager

```sql
SELECT e.name AS employee, m.name AS manager
FROM Employee e
JOIN Employee m ON e.manager_id = m.id
WHERE e.salary > m.salary;
```

### Find pairs of students in the same class

```sql
SELECT a.student_name, b.student_name, a.class
FROM Student a
JOIN Student b ON a.class = b.class AND a.id < b.id;  -- avoid duplicates with id <
```

## Pattern 5: Aggregation with HAVING

```sql
-- Departments with more than 5 employees
SELECT department, COUNT(*) AS emp_count
FROM Employee
GROUP BY department
HAVING COUNT(*) > 5;

-- Products ordered by more than 100 different customers
SELECT product_id, COUNT(DISTINCT customer_id) AS unique_customers
FROM Orders
GROUP BY product_id
HAVING COUNT(DISTINCT customer_id) > 100;

-- Customers who placed orders on every day of last week
SELECT customer_id
FROM Orders
WHERE order_date BETWEEN CURDATE() - INTERVAL 7 DAY AND CURDATE()
GROUP BY customer_id
HAVING COUNT(DISTINCT order_date) = 7;
```

## Pattern 6: LAG / LEAD — Previous/Next Row

```sql
-- Day-over-day change in stock price
SELECT
    trade_date,
    price,
    LAG(price, 1) OVER (ORDER BY trade_date) AS prev_price,
    price - LAG(price, 1) OVER (ORDER BY trade_date) AS daily_change
FROM StockPrice;

-- Find sessions where user came back after a gap of > 7 days
SELECT
    user_id,
    session_date,
    LAG(session_date) OVER (PARTITION BY user_id ORDER BY session_date) AS prev_session,
    DATEDIFF(session_date, LAG(session_date) OVER (PARTITION BY user_id ORDER BY session_date)) AS gap_days
FROM Sessions;
```

## Pattern 7: EXISTS vs IN vs JOIN

```sql
-- Employees who have at least one project (EXISTS — stops at first match, efficient)
SELECT name FROM Employee e
WHERE EXISTS (
    SELECT 1 FROM Project p WHERE p.emp_id = e.id
);

-- Same with IN (loads all project emp_ids into memory — slower for large sets)
SELECT name FROM Employee
WHERE id IN (SELECT emp_id FROM Project);

-- TRAP: IN with NULL → returns empty result!
-- If subquery returns {1, 2, NULL}, then `WHERE id NOT IN (...)` returns NO rows
-- Use NOT EXISTS instead of NOT IN when subquery may contain NULLs

-- Correct version:
SELECT name FROM Employee e
WHERE NOT EXISTS (
    SELECT 1 FROM Project p WHERE p.emp_id = e.id
);
```

## Pattern 8: Date & Time Queries

```sql
-- Orders placed in the last 7 days
SELECT * FROM Orders WHERE order_date >= CURDATE() - INTERVAL 7 DAY;

-- Extract year, month from date
SELECT YEAR(order_date), MONTH(order_date), COUNT(*)
FROM Orders
GROUP BY YEAR(order_date), MONTH(order_date);

-- Find orders on weekdays only
SELECT * FROM Orders WHERE DAYOFWEEK(order_date) NOT IN (1, 7);  -- 1=Sunday, 7=Saturday

-- Age calculation
SELECT name, TIMESTAMPDIFF(YEAR, birth_date, CURDATE()) AS age
FROM Users;
```

## Pattern 9: Recursive CTE — Hierarchical Queries

```sql
-- Traverse employee → manager hierarchy (find all ancestors of emp 5)
WITH RECURSIVE hierarchy AS (
    -- Anchor: start from the target employee
    SELECT id, name, manager_id, 0 AS level
    FROM Employee WHERE id = 5

    UNION ALL

    -- Recursive: go up to manager
    SELECT e.id, e.name, e.manager_id, h.level + 1
    FROM Employee e
    JOIN hierarchy h ON e.id = h.manager_id
)
SELECT * FROM hierarchy;

-- Find all nodes in a category tree
WITH RECURSIVE category_tree AS (
    SELECT id, name, parent_id FROM Category WHERE parent_id IS NULL  -- root

    UNION ALL

    SELECT c.id, c.name, c.parent_id
    FROM Category c
    JOIN category_tree ct ON c.parent_id = ct.id
)
SELECT * FROM category_tree;
```

## Pattern 10: Pivoting / Conditional Aggregation

```sql
-- Count orders per status in one row (pivot)
SELECT
    COUNT(CASE WHEN status = 'pending'   THEN 1 END) AS pending_count,
    COUNT(CASE WHEN status = 'shipped'   THEN 1 END) AS shipped_count,
    COUNT(CASE WHEN status = 'delivered' THEN 1 END) AS delivered_count
FROM Orders;

-- Total revenue per month as columns
SELECT
    SUM(CASE WHEN MONTH(order_date) = 1 THEN amount ELSE 0 END) AS Jan,
    SUM(CASE WHEN MONTH(order_date) = 2 THEN amount ELSE 0 END) AS Feb,
    SUM(CASE WHEN MONTH(order_date) = 3 THEN amount ELSE 0 END) AS Mar
FROM Orders
WHERE YEAR(order_date) = 2024;
```

## Pattern 11: Deduplication

```sql
-- Keep only the most recent record per user (using ROW_NUMBER)
DELETE FROM UserActivity
WHERE id NOT IN (
    SELECT id FROM (
        SELECT id, ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY created_at DESC) AS rn
        FROM UserActivity
    ) t WHERE rn = 1
);

-- Alternative: Keep only the row with the minimum ID per email using a CTE
WITH KeepRows AS (
    SELECT MIN(id) AS id
    FROM Person
    GROUP BY email
)
DELETE FROM Person
WHERE id NOT IN (
    SELECT id
    FROM KeepRows
);

-- Alternative: Keep only the row with the minimum ID using NOT EXISTS
DELETE FROM Person
WHERE id NOT IN (
    SELECT id FROM (
        SELECT p1.id 
        FROM Person p1
        WHERE NOT EXISTS (
            SELECT 1 
            FROM Person p2
            WHERE p1.email = p2.email 
              AND p2.id < p1.id
        )
    ) temp
);

-- Alternative: Direct DELETE using EXISTS (deletes a row if another row with same email and smaller ID exists)
DELETE FROM Person
WHERE EXISTS (
    SELECT 1 
    FROM Person p2
    WHERE Person.email = p2.email 
      AND p2.id < Person.id
);

-- Find duplicate rows
SELECT email, COUNT(*) AS cnt
FROM Users
GROUP BY email
HAVING COUNT(*) > 1;
```

## Pattern 12: Classic Interview Problems

### Problem: Find duplicate transactions (same user, same amount, within 10 minutes)
```sql
SELECT DISTINCT a.transaction_id
FROM Transactions a
JOIN Transactions b
    ON a.user_id = b.user_id
    AND a.amount = b.amount
    AND a.transaction_id <> b.transaction_id
    AND ABS(TIMESTAMPDIFF(MINUTE, a.created_at, b.created_at)) <= 10;
```

### Problem: Users active in Jan 2024 but NOT in Feb 2024
```sql
SELECT DISTINCT user_id FROM Activity
WHERE YEAR(activity_date) = 2024 AND MONTH(activity_date) = 1
  AND user_id NOT IN (
    SELECT DISTINCT user_id FROM Activity
    WHERE YEAR(activity_date) = 2024 AND MONTH(activity_date) = 2
  );
```

### Problem: Department where average salary > company average
```sql
SELECT department, AVG(salary) AS dept_avg
FROM Employee
GROUP BY department
HAVING AVG(salary) > (SELECT AVG(salary) FROM Employee);
```

## Key Rules to Memorise

```
Query execution order:
  FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT

Window functions:
  OVER (PARTITION BY ... ORDER BY ...) — doesn't collapse rows (unlike GROUP BY)
  ROW_NUMBER: always unique | RANK: ties get same rank, gaps | DENSE_RANK: ties, no gaps

NULL rules:
  NULL = NULL  → FALSE (use IS NULL)
  NOT IN with NULL subquery → returns empty set (use NOT EXISTS!)
  COALESCE(col, 0) → replace NULL with default

EXISTS vs IN:
  EXISTS: short-circuits on first match → faster for large subqueries
  IN: loads all values → fast when subquery result is small
  NOT IN + NULL → broken; always use NOT EXISTS

GROUP BY vs PARTITION BY:
  GROUP BY: collapses rows into one per group
  PARTITION BY (window): keeps all rows; computes within each partition
```
