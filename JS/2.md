# Lecture 02: Scopes, Closures & Production Design Patterns

## 1. Scope System & Scope Chain

Scope determines the accessibility/visibility of variables, functions, and objects in a particular part of your code during runtime.

### 1.1 Types of Scope
1. **Global Scope**: Variables declared outside any function or block. Accessible everywhere.
2. **Function Scope**: Variables declared with `var`, `let`, or `const` inside a function are accessible only within that function.
3. **Block Scope (ES6)**: Variables declared with `let` or `const` inside `{ ... }` blocks (e.g. `if`, `for`, `while`) cannot be accessed outside the block.

```javascript
{
  var varScoped = "I leak out of blocks!";
  let letScoped = "I stay inside block!";
  const constScoped = "I also stay inside!";
}

console.log(varScoped); // "I leak out of blocks!"
// console.log(letScoped); // ReferenceError: letScoped is not defined
```

### 1.2 Lexical Scope & Scope Chain
Lexical Scope means that scope is determined at **compile/author time** by where variables and blocks are physically written in the code.

```javascript
const globalVar = "Global";

function outer() {
  const outerVar = "Outer";

  function inner() {
    const innerVar = "Inner";
    console.log(innerVar, outerVar, globalVar); // Scopes searched sequentially upward
  }

  inner();
}

outer();
```
**Scope Chain Lookup**: When a variable is referenced, JS engine checks current local scope -> outer lexical parent scope -> ... -> Global Scope. If not found, throws `ReferenceError`.

## 2. Deep Dive into Closures

A **Closure** is the combination of a function bundled together (enclosed) with references to its surrounding lexical environment. In simple terms: **A inner function always retains access to the variables of its outer parent scope, even after the parent function has finished executing and returned.**

### 2.1 Lexical Environment Mechanics
When a function returns an inner function, the inner function holds a reference to the outer function's Lexical Environment record on the heap (preventing garbage collection of those variables).

```javascript
function createCounter() {
  let count = 0; // Preserved in closure heap storage

  return {
    increment() {
      count++;
      return count;
    },
    decrement() {
      count--;
      return count;
    },
    getCount() {
      return count;
    }
  };
}

const counter = createCounter();
console.log(counter.increment()); // 1
console.log(counter.increment()); // 2
console.log(counter.getCount());  // 2
// count variable is totally private and inaccessible directly from outside!
```

## 3. Production Patterns Utilizing Closures

### 3.1 Data Privacy & Encapsulation
Before ES6 private class fields (`#field`), closures were the primary way to achieve strict variable encapsulation.

```javascript
function createBankAccount(initialBalance) {
  let balance = initialBalance; // Private field

  return {
    deposit(amount) {
      if (amount <= 0) throw new Error("Invalid amount");
      balance += amount;
      return balance;
    },
    withdraw(amount) {
      if (amount > balance) throw new Error("Insufficient funds");
      balance -= amount;
      return balance;
    },
    getBalance() {
      return balance;
    }
  };
}

const account = createBankAccount(1000);
account.deposit(500);
console.log(account.getBalance()); // 1500
console.log(account.balance); // undefined (Safe from external mutation!)
```

### 3.2 Function Currying & Partial Application
Currying transforms a function taking multiple arguments `f(a, b, c)` into a sequence of unary functions `f(a)(b)(c)`.

```javascript
// Generic Curry Implementation
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    } else {
      return function(...nextArgs) {
        return curried.apply(this, args.concat(nextArgs));
      };
    }
  };
}

// Usage Example
const sum = (a, b, c) => a + b + c;
const curriedSum = curry(sum);

console.log(curriedSum(1)(2)(3)); // 6
console.log(curriedSum(1, 2)(3)); // 6
console.log(curriedSum(1)(2, 3)); // 6
```

### 3.3 Production Memoization Cache
Memoization optimizes computationally expensive functions by caching results based on arguments.

```javascript
function memoize(fn) {
  const cache = new Map(); // Closured cache storage

  return function(...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) {
      console.log(`Fetching from cache for args: ${key}`);
      return cache.get(key);
    }

    console.log(`Calculating result for args: ${key}`);
    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}

// Usage
const slowSquare = (n) => {
  // Simulate heavy work
  for (let i = 0; i < 1e7; i++) {}
  return n * n;
};

const fastSquare = memoize(slowSquare);
console.log(fastSquare(5)); // Calculating... -> 25
console.log(fastSquare(5)); // Fetching from cache... -> 25
```

## 4. Stale Closures & Practical Pitfalls

### 4.1 The Classic Loop Gotcha

```javascript
// Problem with var
for (var i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log("var loop:", i); // Logs: 3, 3, 3 (Shared function scope)
  }, 100);
}

// Fix Option 1: Use let (creates new block scope per iteration)
for (let i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log("let loop:", i); // Logs: 0, 1, 2
  }, 100);
}

// Fix Option 2: IIFE Closure binding (used prior to ES6)
for (var j = 0; j < 3; j++) {
  ((jCopy) => {
    setTimeout(() => {
      console.log("IIFE loop:", jCopy); // Logs: 0, 1, 2
    }, 100);
  })(j);
}
```

### 4.2 Stale Closures in Asynchronous Code & React
A **Stale Closure** occurs when a inner function captures state variables from an earlier render/execution cycle, and fails to see updated variable references.

```javascript
function createStaleTimer() {
  let value = 0;

  const logValue = () => {
    console.log("Captured value:", value);
  };

  setInterval(() => {
    value++; // State updates externally
  }, 1000);

  return logValue; // Captured value when value was 0!
}

const log = createStaleTimer();
setTimeout(() => {
  log(); // Output: "Captured value: 0" (Even though value is now ~3!)
}, 3000);
```

**How to Fix Stale Closures**:
1. Always pass state setters/getters instead of raw primitive variables.
2. In React, use `useRef` to maintain a mutable reference that bypasses closure capture, or include state variables in hook dependency arrays.
