# Lecture 03: `this` Keyword, Prototypes, OOP & Object Manipulation

## 1. Demystifying the `this` Keyword

Unlike lexical scope (determined at compile time), `this` binding is **dynamic** and determined at **runtime** based on **how and where a function is called**.

### 1.1 The 5 Rules of `this` Binding

#### Rule 1: Default Binding
When a standalone function is invoked directly:
- In non-strict mode: `this` refers to `window` (browser) or `global` (Node).
- In strict mode (`"use strict"`): `this` is `undefined`.

```javascript
function show() {
  console.log(this);
}
show(); // window / global (or undefined in strict mode)
```

#### Rule 2: Implicit Binding
When a function is called as a method of an object, `this` points to the object preceding the dot (`.`).

```javascript
const user = {
  name: "Alice",
  greet() {
    console.log(`Hello, ${this.name}`);
  }
};

user.greet(); // "Hello, Alice" (Implicitly bound to user)

// Losing Implicit Context Gotcha:
const greetFn = user.greet;
greetFn(); // "Hello, undefined" (Falls back to Default Binding!)
```

#### Rule 3: Explicit Binding (`call`, `apply`, `bind`)
Explicitly force `this` context onto a function call.

- `call(thisArg, arg1, arg2, ...)`: Invokes immediately with comma-separated arguments.
- `apply(thisArg, [arg1, arg2, ...])`: Invokes immediately with an array of arguments.
- `bind(thisArg, arg1, ...)`: **Returns a new bound function** with fixed `this`.

```javascript
function introduce(greeting, punctuation) {
  console.log(`${greeting}, I am ${this.name}${punctuation}`);
}

const obj = { name: "Bob" };

introduce.call(obj, "Hi", "!");       // "Hi, I am Bob!"
introduce.apply(obj, ["Hello", "."]); // "Hello, I am Bob."

const boundFn = introduce.bind(obj, "Hey");
boundFn("?");                         // "Hey, I am Bob?"
```

#### Rule 4: `new` Binding
When a function is invoked with the `new` keyword, JS performs 4 steps:
1. Creates a brand new empty object `{}`.
2. Links object's `[[Prototype]]` to the constructor function's `.prototype`.
3. Binds `this` inside constructor to the new object.
4. Returns the object (unless constructor explicitly returns another object).

```javascript
function Person(name) {
  this.name = name;
}
const p = new Person("Charlie");
console.log(p.name); // "Charlie"
```

#### Rule 5: Arrow Functions (Lexical `this`)
Arrow functions **do not** have their own `this`. They capture `this` lexically from their enclosing parent context at execution time. `call`/`apply`/`bind` cannot override an arrow function's `this`.

```javascript
const timer = {
  seconds: 0,
  start() {
    // Arrow function inherits `this` from timer object inside start()
    setInterval(() => {
      this.seconds++;
      console.log(this.seconds);
    }, 1000);
  }
};
timer.start();
```

## 2. Hand-written Polyfill: `Function.prototype.myBind`

```javascript
Function.prototype.myBind = function (context, ...outerArgs) {
  if (typeof this !== "function") {
    throw new TypeError("myBind must be called on a function");
  }

  const originalFn = this;

  return function (...innerArgs) {
    // Combine outer bound arguments with new arguments passed at call-site
    return originalFn.apply(context, [...outerArgs, ...innerArgs]);
  };
};

// Testing custom polyfill
function multiply(factor, number) {
  return `${this.label}: ${factor * number}`;
}

const double = multiply.myBind({ label: "Result" }, 2);
console.log(double(5)); // "Result: 10"
```

## 3. Prototypes & Prototypal Inheritance

JavaScript uses **Prototypal Inheritance** rather than classical inheritance. Every JS object has an internal hidden property `[[Prototype]]` (accessible via `__proto__` or `Object.getPrototypeOf()`).

### 3.1 `prototype` vs `__proto__`
- `prototype`: A property present **only on constructor functions** (and classes). Defines properties/methods that instances will inherit.
- `__proto__`: A getter/setter property on **all object instances** pointing to their parent prototype object.

```
+------------------+                    +------------------------+
|  p1 (Person instance)                 | Person.prototype       |
+------------------+                    +------------------------+
| name: "Alice"    |                    | constructor: Person    |
| __proto__ -------+------------------->| sayHi: function()      |
+------------------+                    | __proto__ -------------+---+
                                        +------------------------+   |
                                                                     v
                                                        +------------------+
                                                        | Object.prototype |
                                                        +------------------+
```

```javascript
function Animal(name) {
  this.name = name;
}
Animal.prototype.eat = function() {
  console.log(`${this.name} is eating.`);
};

const dog = new Animal("Rex");
dog.eat(); // "Rex is eating." (Found on Animal.prototype via prototype chain)

console.log(dog.__proto__ === Animal.prototype); // true
console.log(Animal.prototype.__proto__ === Object.prototype); // true
console.log(Object.prototype.__proto__); // null (End of chain)
```

### 3.2 ES6 Classes (Syntactic Sugar)
Classes provide a cleaner syntax for prototypal inheritance.

```javascript
class Vehicle {
  constructor(brand) {
    this.brand = brand;
  }
  start() {
    console.log(`${this.brand} starting...`);
  }
}

class Car extends Vehicle {
  constructor(brand, model) {
    super(brand); // Calls Vehicle constructor
    this.model = model;
  }
  drive() {
    console.log(`Driving ${this.brand} ${this.model}`);
  }
}

const myCar = new Car("Toyota", "Camry");
myCar.start(); // "Toyota starting..."
myCar.drive(); // "Driving Toyota Camry"
```

## 4. Object Integrity & Cloning Strategies

### 4.1 Property Descriptors & Integrity
```javascript
const user = { name: "David" };

// Object.freeze -> Read-only (Cannot add, delete, or modify existing properties)
Object.freeze(user);
// user.name = "John"; // Fails silently in non-strict mode, throws error in strict mode!

// Object.seal -> Cannot add or delete properties, but CAN modify existing values
const obj = { age: 25 };
Object.seal(obj);
obj.age = 26; // Works!
delete obj.age; // Fails!
```

### 4.2 Shallow vs Deep Copying

```javascript
const original = {
  a: 1,
  nested: { b: 2 }
};

// 1. Shallow Copy (Spread / Object.assign)
const shallow = { ...original };
shallow.nested.b = 999;
console.log(original.nested.b); // 999! (Nested objects share memory reference!)

// 2. Modern Deep Copying with structuredClone (Native ES2022)
const deep = structuredClone(original);
deep.nested.b = 42;
console.log(original.nested.b); // 999 (Unchanged! Truly deep copied)

// Limits of JSON.parse(JSON.stringify(obj)):
// Drops Functions, Symbol keys, undefined, converts Date to string, throws on Circular references!
```
